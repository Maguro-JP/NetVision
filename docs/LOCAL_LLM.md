# 手元のモデルを使う

NetVision は、モデルが無くても全部の機能が動きます。モデルを置くと、そこに
「取り込んだ資料を根拠に Config を下書きする」が加わります。

閉域が前提なので、宛先は手元か社内に立てたものだけです。外の事業者へは、
`NETVISION_LLM_ALLOW_EXTERNAL=true` を明示するまで一切送りません。

## どのモデルを選ぶか

商用利用のことまで含めて、まずは Qwen 系が扱いやすいです。用途で必要な賢さが
違うので、役割を分けて置けるようにしてあります。

| 役割 | 使いどころ | 目安 |
|---|---|---|
| `quick` | 資料の要約・分類・言い換え | 3B 前後。CPU でも動く |
| `deep` | Config の下書き、構成のレビュー | 7B〜14B。コード寄りのモデルが向く |

1台で試すなら `deep` に `qwen2.5-coder:7b`、その1つだけで始めて構いません。
置いていない役割は、置いてある方へ回ります。

## アプリの中で動かす（新しいソフトを入れない）

端末に新しい実行ファイルを置けない場合の道です。増えるのは NetVision が使う
ライブラリ1つだけで、実行ファイルは増えず、外にも出ません。

モデルの実体（GGUF ファイル）は、アプリの隣の `models` フォルダに置きます。
ファイル名は問いません。複数置くと、名前から使い分けます（3B のような小さいものを
要約に、大きいものを Config の下書きに）。

```
NetVision/
  models/
    qwen2.5-3b-instruct-q4_k_m.gguf
    qwen2.5-coder-7b-instruct-q4_k_m.gguf
```

置き場所を変えるなら `NETVISION_MODEL_DIR`、1つを名指しするなら
`NETVISION_MODEL_PATH` です。何も置かなければ、規則ベースだけで動きます。

### モデルの入手先

公式の配布元はここです。

- Qwen: https://huggingface.co/Qwen

この中から、名前に `GGUF` が付いたものを選び、ファイルを1つ落とします。
版が上がると名前が変わるので、個別のファイル名は書きません。選び方だけ
覚えておけば足ります。

- 大きさ: 要約・分類なら 3B、Config の下書きなら 7B
- 量子化: 迷ったら `Q4_K_M`。品質と大きさの釣り合いが良く、実質の標準
- 目安: 3B の Q4_K_M で約 2GB、7B で約 4.7GB

落とすのは、インターネットに出られる端末で行い、閉域へはファイルを持ち込みます。
ライセンスは Apache 2.0（Qwen2.5 の多くのサイズ）。配る一式に同梱するときは、
LICENSE も一緒に入れてください。

モデルを読むためのライブラリは、配る一式に既定で入ります（実行ファイルは増えません）。
使う人がやることは、GGUF を1つ置くことだけです。

モデルの実体まで同梱するなら、作成スクリプトに GGUF の URL かパスを渡します。
既定では同梱しません（一式が数 GB 大きくなるため）。

```
WITH_MODEL=https://…/qwen2.5-coder-7b-instruct-q4_k_m.gguf ./packaging/make-bundle-windows.sh
```

```
./packaging/make-bundle-windows.ps1 -WithModel C:\models\qwen2.5-coder-7b.gguf
```

モデルの実体をリポジトリに置かないのは、GitHub が1ファイル 100MB までという
制約があるためと、モデルは数か月で新しいものが出るためです。アプリと一緒に
固定すると、入れ替えのたびにアプリごと配り直すことになります。

## 使うのを止める

置いてあっても切れます。規則ベースだけのときと結果を見比べたい、遅いので
一時的に止めたい、という場面のためです。

```
NETVISION_LLM_ENABLED=false
```

いまどうなっているかは、画面の「設定」に出ます。

## 何を入れるか（端末の制約で選ぶ）

NetVision は OpenAI 互換の口へ問い合わせるだけで、モデルを動かすソフトは
同梱していません。入れるものは、端末の決まりに合わせて選びます。

| | llama.cpp の server | Ollama |
|---|---|---|
| 入れ方 | 実行ファイルを置くだけ。インストール不要 | インストーラー。利用者ごとに入る |
| 常駐 | 動かしたときだけ | ログオンのたびに立ち上がる |
| 利用者登録 | 不要 | ローカルで動かすだけなら不要 |
| モデルの入手 | GGUF ファイルを手で置く | `ollama pull`（外への通信が要る） |
| 更新の確認 | しない | する（外への通信） |

インストールや常駐に決まりのある端末では、llama.cpp の server が扱いやすい
です。実行ファイルとモデルのファイルを置くだけで、常駐もせず、外へも出ません。

```
llama-server.exe -m qwen2.5-coder-7b-q4_k_m.gguf --host 127.0.0.1 --port 8080
```

```
NETVISION_LLM_URL=http://127.0.0.1:8080/v1
NETVISION_LLM_MODEL=qwen2.5-coder-7b
```

どちらを選んでも、NetVision 側の設定は同じです。

## 立てる（Ollama の場合）

手元で気軽に試すなら Ollama が早いです。ただし、次の点は導入前に
確認してください。

- インストーラーで入り、ログオンのたびに常駐する（管理者権限は不要ですが、
  常駐そのものが決まりに触れる職場があります）
- モデルを取ってくるときに外（ollama.com）へ出る。閉域では、別の端末で
  落としたモデルのフォルダを持ち込む
- 更新の確認で外へ出る。閉域では通らないので、その分だけ起動が遅くなることがある
- 入力した内容（Config や資料）が外へ送られることはありません。処理は手元で
  完結します

会社の決まりで確認が要る場合は、上の4点を並べて出せば足ります。

```
ollama pull qwen2.5-coder:7b
ollama serve
```

NetVision 側は環境変数だけです。

```
NETVISION_LLM_URL=http://127.0.0.1:11434/v1
NETVISION_LLM_MODEL=qwen2.5-coder:7b
```

役割で分けるときは、こちらが優先されます。

```
NETVISION_LLM_PROFILES=[
  {"role": "quick", "url": "http://127.0.0.1:11434/v1", "model": "qwen2.5:3b"},
  {"role": "deep",  "url": "http://10.0.0.50:8000/v1",  "model": "qwen2.5-coder:14b"}
]
```

設定できたら、画面の「設定」に状態が出ます。使える／外向きなので止めている／
設定が足りない、のどれかが見えます。

## 閉域へ持ち込む

インターネットに出られない環境では、モデルのファイルを別の端末で落として
持ち込みます。Ollama なら、モデルの実体は次の場所にあります。

- Windows: `%USERPROFILE%\.ollama\models`
- Linux: `/usr/share/ollama/.ollama/models` または `~/.ollama/models`

このフォルダごとコピーすれば、閉域側でも `ollama run` できます。

## 端末に何も入れられない場合

インストールが許されない職場では、会社が承認している AI（M365 Copilot など）を
人が使う形にできます。アプリから呼ぶのではなく、貼って戻すだけです。

1. 「Config 計画」でやりたいことを書き、「貼る文を作る」を押す
2. 出てきた文をコピーして、承認済みの AI に貼る
3. 返ってきた設定を、同じ画面に貼り戻して「貼った設定を検める」を押す

依頼文には、取り込んだ資料の該当箇所と現行 Config が入ります。返ってきた設定は、
モデルを置いた場合とまったく同じ道を通ります（資料との突き合わせ、通信に影響する
行の印）。生成をどこでやっても、検める側はこちらに残る作りです。

実機の Config を外へ貼ることになるので、職場の決まりを確かめてください。

## 使い方

「Config 計画」で将来フルを編集しているときに、やりたいことを言葉で書くと
下書きが出ます。作りは3段です。

1. 取り込んだベンダー資料から、その依頼に関係する章を探す（DB の中だけで完結）
2. その章に出てくる書き方だけを材料に、下書きを起こす
3. 出てきた行を資料と突き合わせ、裏付けの無い行と、通信に影響する行に印を付ける

3 は必ず通ります。モデルの出力をそのまま人へ渡すと、資料に無い書き方が混ざって
いても気付けないためです。モデルが無い環境でも 1 と 3 は動くので、資料から
拾ったコマンドが手がかりとして出ます。

ここで作るのは下書きだけで、実機には投入しません。

## 速さの目安

1台の PC で動かす場合、7B クラスなら CPU でも待てる速さ（数十秒）です。
GPU があれば数秒に落ちます。要約のような軽い用途に大きいモデルを使うと、
待ち時間だけが伸びるので、役割を分けて置くほうが結果的に速く感じます。
