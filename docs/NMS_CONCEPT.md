# ネットワーク管理システムとして育てる場合の構想

このソフトは今のところ「台帳と構成図」です。実機には触らず、Config を読んで
図と表を出すところまでを担当しています。

その延長で、通信量や機器の状態を可視化する管理システムとして売るなら何が要るかを
まとめます。ここでは構想だけで、実装はしていません。

---

## 1. 何が足りないのか

見せ方はほぼ揃っています。トポロジ図・立体表示・結線表・ポート割付は、
値さえあればそのまま使えます。足りないのは値を集める仕組みです。

今の作りは「機器に触らない」ことを前提にしています。ここを変えるのが一番大きい判断で、
技術より先に決めるべきことがあります（4章）。

---

## 2. 集め方の選択肢

| 方式 | 取れるもの | 間隔 | 実装の重さ | 対応機器 |
|---|---|---|---|---|
| SNMP ポーリング | ポートの入出力バイト数・エラー数・稼働状態 | 30秒〜5分 | 軽い | ほぼ全部 |
| SNMP Trap 受信 | リンクダウンなどの事象 | 即時 | 軽い | ほぼ全部 |
| gNMI / streaming telemetry | 同上をより細かく | 1〜10秒 | 中 | 新しめの機器のみ |
| sFlow / NetFlow / IPFIX | どこからどこへ、どのポート番号で | 数秒〜1分 | 重い | 対応機種に限る |
| ICMP / TCP の疎通確認 | 到達性・遅延 | 10秒〜1分 | 軽い | 全部 |

最初に入れるなら SNMP ポーリングと疎通確認です。この2つで
「落ちている」「詰まっている」がほぼ言えます。

「どこからどこへ流れているか」を図に出したい場合だけ、sFlow / NetFlow が要ります。
立体表示の光の玉を実データに置き換えるのはこれに当たります。

---

## 3. 置き場所と構成

収集は本体とは別のプロセスに分けます。

```
[収集プロセス] --SNMP/ICMP--> 機器
      |
      v
[時系列データベース]  <-- 本体は読むだけ
      |
      v
[NetVision 本体] --> 図・表・画面
```

分ける理由は2つあります。

1. 認証情報の置き場所を1か所に閉じ込められる。本体は読むだけなので、
   画面側に穴があっても機器の認証情報には届かない
2. 収集が止まっても画面は出る。逆に画面を落としても収集は続く

時系列データは行数が多くなります。ポート1つを1分間隔で1年貯めると
50万行を超えるので、既存のテーブルとは別に持ちます。
候補は Prometheus / VictoriaMetrics / InfluxDB / TimescaleDB あたりです。
閉域で動かす前提なので、単体で動いて外に出ないものを選びます。

---

## 4. 先に決めておくべきこと

技術の選定より前に、ここが決まらないと作れません。

### 4.1 認証と権限

機器の認証情報を持った時点で、このソフト自体が守るべき対象になります。
現状は認証が無く、既定で 127.0.0.1 にだけ待ち受けています。
収集を入れるなら、認証・権限・監査ログが先です。

### 4.2 機器に対して何をしてよいか

読むだけか、設定も投入するか。今は Config を生成するところまでで、投入はしません。
投入まで踏み込むなら、承認の流れ・実行記録・切り戻しが要ります。
可視化と設定投入は別の製品と考えた方が安全です。

### 4.3 どこまで貯めるか

保持期間で必要な容量が決まります。1年か3年か、1分間隔か5分間隔か。
後から短くするのは簡単ですが、長くするのは後追いできません。

### 4.4 誤解を招かない見せ方

今の立体表示の光はランダムです。実データに置き換えるなら、
どちらなのかが画面で必ず分かるようにします。演出と実測が混ざると、
「流れているから通信している」と読まれて判断を誤ります。

---

## 5. 段階の案

1. 疎通確認だけ入れる。落ちている機器が図で色分けされる
2. SNMP でポートの入出力を取る。線の太さ・色に反映する
3. しきい値と通知。詰まっているポートを指摘に出す
4. sFlow / NetFlow。どこからどこへを図に出す
5. 事象の相関。1本の回線断で影響を受けた拠点を出す

1と2までで「管理システム」と呼べる形になります。3以降は他製品との差別化の話です。

---

## 6. 今のうちにやっておくとよいこと

実装しなくても、後で効くもの。

- 拠点に緯度経度の項目を持たせる。地図表示が住所文字列の照合に頼らなくなる
- 機器にポーリング対象かどうかの印を持たせる。全台に投げると数万台では破綻する
- 収集の設定（コミュニティ名・認証情報）を置く場所を決めておく。
  台帳と同じ DB に平文で置かないこと
