# データの守り方をどうするか

NetVision の DB には、Config 一式と同じ重みの情報が入ります。機器名・管理IP・
ポートの割付・拠点の住所、そして取り込んだ Config の原文です。原文を残して
いるのは、パーサを直したときに読み直せるようにするためです。

画面と差分では、パスワードや鍵・コミュニティ名を伏せるようにしました
（`app/services/secrets.py`）。ここで扱うのは、その次の話です。DB ファイル
そのものを持ち出されたときにどうするか。

## いまの状態

| どこ | いまどうなっているか |
|---|---|
| NetVision へのログイン | ありません。だから既定で `127.0.0.1` にしか待ち受けません |
| 機器のログイン情報 | 持っていません。実機に触らないので要りません |
| Config の原文 | DB にそのまま入っています（パスワードの行を含む） |
| 画面・差分 | 秘密は伏せて出します |
| 外部の AI へ送るとき | 管理IP・鍵・コミュニティ名を伏せてから送ります |
| DB ファイル | 素のままです。読める人は中身を全部読めます |

つまり、いまの前提は「DB ファイルを、Config 一式と同じ扱いで守る」です。
持ち出されたら、Config を持ち出されたのと同じことになります。

## 選択肢

### 1. OS のディスク暗号化に任せる（推奨）

Windows なら BitLocker、macOS なら FileVault。端末が配布物であれば、たいてい
すでに掛かっています。

- 良いところ: 追加の実装がゼロ。鍵の管理も情シスの既存の仕組みに乗る
- 弱いところ: 端末が動いている状態でファイルを取られると効きません
  （ログインしている人には読めるため）
- 向くのは: 1人が自分の端末で使う、いまの使い方

まず確かめるべきは「この端末に既に掛かっているか」です。掛かっているなら、
NetVision 側で暗号化を足しても、増える守りは限定的です。

### 2. DB ファイルを暗号化する（SQLCipher など）

SQLite を暗号化した形で持ちます。

- 良いところ: ファイル単体を持ち出されても読めません
- 弱いところ:
  - 鍵をどこに置くかが新しい問題になります。ファイルの隣に置けば意味が無く、
    起動のたびに人が打つなら、それは NetVision のログインを作るのと同じ手間です
  - 配布物に SQLCipher を同梱する必要があります（いまの「インストール不要」の
    形は保てますが、ビルドが1つ増えます）
  - 壊れたときに直せる人が減ります。素の SQLite なら他の道具でも開けますが、
    暗号化するとその道が閉じます
- 向くのは: 端末を共有している、または持ち出す使い方

### 3. Config の原文を暗号化して持つ

DB は素のまま、`config_snapshots.content` だけを暗号化します。

- 良いところ: 秘密が集中している場所だけを守れます。台帳（機器名や IP）は
  そのままなので、検索も速いままです
- 弱いところ: 鍵の置き場所の問題は 2 と同じです。加えて、全文検索が効かなく
  なります（いまは資料の全文検索に使っています）
- 向くのは: Config だけが特に機微、という判断をした場合

### 4. そもそも秘密を保存しない（取り込み時に伏せる）

取り込んだ時点で、パスワードの行を伏せた形にして保存します。

- 良いところ: 持ち出されても、そこには何も無い
- 弱いところ: 元に戻せません。差分を取るときに「変わったかどうか」も
  分からなくなります（伏せた値どうしは常に同じに見えるため）。
  実機との突き合わせにも使えなくなります
- 向くのは: 「Config の秘密は NetVision に置かない」と決め切れる場合

## 判断のしかた

先に決めるのはこの2つです。

1. その端末に、既にディスク暗号化が掛かっているか
2. DB ファイルを、その端末の外（共有フォルダ、バックアップ）へ出すか

1 が掛かっていて 2 が「出さない」なら、いまのままで釣り合っています。
実装を足すより、置き場所の決めごとを書いておくほうが効きます。

2 が「出す」なら、出す先での守りを先に考えます。共有フォルダに置くなら、
そのフォルダの権限が実質の守りになります。暗号化を足しても、鍵を同じ場所に
置けば意味がありません。

複数人で使うなら、暗号化より先に NetVision のログインが要ります。
「誰が見たか」が残らないほうが、たいていの現場では問題になります。

## いま決めておくとよいこと

- DB の置き場所を決めて書いておく（既定は `~/.netvision`）
- バックアップの置き場所も同じ扱いにする。守りはいちばん緩いところで決まります
- 端末を手放すときの手順（DB ファイルを消す）を決めておく
- 画面共有では、伏せた表示のまま見せる。原文を出す口（`?reveal=true`）は
  意識して使う
