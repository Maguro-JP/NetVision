# NetVision を AI の道具として使う（MCP）

NetVision の台帳を、手元の AI から直接引けるようにする口です。
「本社コアの保守はいつまで？」と聞けば、AI が NetVision に問い合わせて答えます。
画面を開いて探す手間が減ります。

読むだけの口です。台帳を書き換える道具は置いていません。

## 何が起きて、何が起きないか

- 標準入出力でやり取りします。NetVision から外へ出る通信はありません
- 動くのは、AI の側から呼ばれたときだけです。常駐はしません
- 台帳の中身は、AI に渡した分だけ AI 側の履歴に残ります。外部の AI に
  つなぐ場合は、渡してよい情報かどうかを先に決めてください
- 閉域のまま使うなら、ローカルのモデル（[LOCAL_LLM.md](LOCAL_LLM.md)）と
  組み合わせてください

## 使える道具

| 名前 | できること |
| --- | --- |
| `list_devices` | 語で機器を探す。ホスト名・管理ID・メーカー・型番・拠点などから当てる |
| `get_device` | 1台を詳しく見る。管理ID / ホスト名 / 呼び名のどれでも引ける。結線も付く |
| `device_summary` | 台帳全体の内訳。総数、重要度ごと、メーカーごとの件数 |
| `list_links` | その機器の結線相手と、使っているポート |
| `list_sites` | 拠点の一覧と、拠点ごとの機器台数 |

一度に返すのは 200 件までです。多く求められても、そこで切ります。

## つなぎ方

配布版（インストール不要版）なら、フォルダの中の `NetVision-mcp.bat` を
AI 側の設定に書くだけです。

```json
{
  "mcpServers": {
    "netvision": {
      "command": "C:\\NetVision\\NetVision-mcp.bat"
    }
  }
}
```

開発中のソースから動かす場合は、`backend` フォルダで次を実行します。

```bash
python -m app.mcp_server
```

設定の書き場所は AI 側の製品によって違います。手元の AI の説明を見てください。

## 確かめ方

正しく動いているかは、手で1行流せば分かります。

```bash
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | python -m app.mcp_server
```

道具の一覧が JSON で返れば、口は開いています。

## この先

いまは読むだけです。「この機器を足したらどうなるか」を試させる口は、
まだ置いていません。書き換えの口を足すときは、必ず下書き（案）として
残る形にして、そのまま台帳に入らないようにします。
