## CSV の書き出しで、= で始まる値をどう扱うか（2026-09-27 JST）

- 何を決めてほしいか: 台帳などの CSV を Excel で開くと、`=` `+` `-` `@` で始まる値が
  式として動く（CSV インジェクション）。`=HYPERLINK(...)` を機器名に入れると、開いた人の
  Excel でリンクになる。xlsx の書き出しは値を変えずに防げたので直した（同じ日のコミット）。
  CSV は値そのものを変えるしか防ぎようがない。
- 選択肢:
  1. `=` `+` `@` で始まる値の先頭に `'` を付けて書き、取り込みでは先頭の `'` を1つ外す
     （`-` は「空」の印や負の数で使われるので外す）
  2. CSV はそのまま出し、画面の書き出しボタンに「Excel で開くなら xlsx を使う」と書く
  3. このまま
- 推す案: 1。書き出し→直して→取り込みで値は元に戻る。ほかのシステムに渡す CSV では
  先頭に `'` が付いた値になる点が欠点。
- 止まっているもの: なし（xlsx は直した。CSV だけ保留）
- 答え: 1 で入れる（2026-09-28 JST、利用者の返答）。見た目が汚れないよう、`'` を付ける値は式の形のものに絞った。
  経緯は docs/knowledge/decisions.md。

## DNS リバインディングへの備え（Host の検査）を入れるか（2026-09-27 JST）

- 何を決めてほしいか: 別サイトからの書き換えは Origin で断った（03c574d）。ただし攻撃者が自分の
  ドメイン名を途中から 127.0.0.1 に向け直す手口（DNS リバインディング）では、Origin と Host が
  どちらも攻撃者の名前で一致するので通る。読み取りも同じく通る。塞ぐには、Host が知っている名前の
  ときだけ応じる検査が要る。名前で開いている人（例: `http://netvision-pc:8000`）がいると、その人は
  設定を足すまで開けなくなるので、入れるかどうかを決めてほしい。
- 選択肢:
  1. Host が localhost・127.0.0.1・::1、IP アドレスそのもの、`NETVISION_ALLOWED_HOSTS` に並べた名前の
     どれかなら通し、それ以外は 400 にする。リバインディングは必ず名前で来るので、IP で開く LAN の
     使い方は設定なしで動く
  2. 既定は今のまま（検査しない）で、`NETVISION_ALLOWED_HOSTS` を書いたときだけ検査する
  3. 入れない
- 推す案: 1。設定なしで塞がり、壊れるのは「名前で開いている」使い方だけ。その場合も画面に
  「NETVISION_ALLOWED_HOSTS にこの名前を足す」と出す。
- 止まっているもの: なし
