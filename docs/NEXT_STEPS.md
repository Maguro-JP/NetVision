# これからやること・確認しておいてほしいこと

デモとして見せられる状態にはなりました。ここから実運用に入るまでに何が要るかを
まとめます。優先順に並べてあります。

---

## 1. 実運用の前に必ず片付けるもの

### 1.1 認証・認可（最優先・ブロッカー）

今は認証がありません。 URL を知っていれば誰でも全部見られます。だから既定で
`127.0.0.1` にだけ待ち受けています。

Config には管理IP・ACL・SNMP コミュニティ名が入ります。攻撃者にとっては
そのまま設計図なので、複数人で使う段階では認証なしに置けません。

| やり方 | 手間 | 向いている場面 |
|---|---|---|
| リバースプロキシで Basic 認証 | 小 | まず数人で使い始める。現実的な第一歩 |
| アプリ内アカウント（ID/パスワード + 役割） | 中 | 「誰が変更したか」を残したい |
| OIDC / LDAP 連携 | 大 | 社内の認証基盤に合わせる必要がある |

進める前に決めてほしいこと:

- 誰が見られるべきか（NW 担当だけ / 情シス全体 / 委託先も）
- 見るだけの人と変更できる人を分ける必要があるか
- 社内に使える認証基盤があるか（あるなら最初からそれに寄せた方が早い）

### 1.2 バックアップから戻せることの確認

手順は `docs/OPERATIONS.md` に書きましたが、戻す方を試していないバックアップは
バックアップではありません。 本番に入れる前に一度、別の場所へ復元してください。

1台完結モードなら `~/.netvision` をコピーするだけです。Docker なら DB とファイル領域の
2系統が要ります（資料の実体は DB の外にあります）。

### 1.3 データの置き場所についての合意

このツールを動かす端末・サーバーは、実質的に構成情報の集約先になります。
社内規程上どの区分にあたるか、持ち出し可否を先に確認しておいてください。
後から「その端末には置けない」となると、移行がやり直しになります。

## 2. 実データでしか分からないこと（試すときの重点）

ここが一番大事です。手元のサンプルで動いても、実機の出力で動くとは限りません。
読めないパターンが出たら、その出力を控えて渡してください。パーサは直せます。

| 確認すること | 見方 | 駄目だったときの影響 |
|---|---|---|
| NEC IX の LLDP 出力 | トポロジーに線が出るか | 公開書式から実装。IX-R/IX-V の公式コマンドリファレンス（HTML）には LLDP のコマンドが無く、IX2000/IX3000 のコマンドリファレンス（PDF）はこの環境から読めていないので公式未確認。結線が引けないときは実出力を渡してほしい |
| NEC IX の書き方 | 機器ページのポート表・経路・NAT・DHCP・OSPF・VRRP | IX-R/IX-V の公式コマンドリファレンス 1.5a の入力形式（`ip address`・`ip route`・`ip napt`・`ip dhcp`・`ip router ospf`・`vrrp`・`tunnel`）で確認済み。IX2000/IX3000 固有の差分は PDF が読めておらず未確認 |
| アラクサラ AX の出力 | 型番・バージョン・ポートが入るか | `show version` は公式マニュアルの出力例（AX3650S アップグレードガイド）で確認済み。ポート表は公開書式から実装で、実機では未検証 |
| NEC QX の display 出力 | 型番・バージョンが入るか | 版によって書式が違う可能性。公式のコマンドマニュアルにはまだ当たれていない（公式未確認）。`display version` の実サンプルがあれば渡してほしい |
| Catalyst の show version | 型番が取れるか | 2960〜9500 で確認済み。取れないと EoL も CVE も引けない |
| トランクの許可 VLAN | ポート表の「トランク許可」 | `add` の複数行・`except`・`none` は対応済み |
| VRF の書き方 | VRF 一覧に出るか | 5ベンダー分実装済み |
| 文字コード | 文字化けしないか | UTF-8 / Shift_JIS / EUC-JP 対応済み。判別を取り違えないことも試験で押さえてある |
| ベンダーの判別 | 画面の「メーカー」が合っているか | 16 ベンダー。名乗りや型番が無いものは判別しない（別ベンダーとして読むより、読めないと言うほうが害が小さい） |
| 規模 | 図が読めるか | 120台・128本で描けることは確認済み（下記）。それ以上は未確認 |

### 特に見てほしいのは「型番が読めない機器の割合」

型番はこのツールの軸です。読めないと EoL も脆弱性も引けません。取り込み結果に
「型番が読み取れないため登録していません」が何件出るかを見てください。
多いようなら、`show version` の収集方法から見直す必要があります。

### 規模の話

デモは57拠点・120台・結線128本です。この規模では、全体図がブラウザで描けること、
拠点で絞るとその拠点ぶん（本社なら8台・9本）に減ることを確認しています。応答は
全体図で1秒弱、他の画面は0.2秒未満でした。

ただし全体図は、台数が増えると人が読めなくなります。読むための図としては、拠点で
絞る使い方が現実的です。自動配置は種別ごとの段組みなので、1拠点20〜30台くらいまでは
持ちますが、それ以上は人が並べ直す前提になります。

数百台を超えたときの見え方は確認していません。

## 3. 何をテストで固定してあるか

「動きました」ではなく、壊れたら気づける形にしてある部分です。
実データで問題が出たときに、どこを疑うべきかの手がかりにもなります。

| 対象 | 内容 |
|---|---|
| 全体 | 1,995 tests（backend）+ 218（frontend） |
| Config 差分 | 生成した差分を別経路で適用し直して、将来フルに一致するか検証。一致しなければコマンドを出さない |
| Config 差分（負荷） | 20,000 通りのランダム変更で、誤った差分・黙った失敗ともに 0 件 |
| 図のラベル配置 | 出力した SVG を読み直して矩形の重なりを判定。乱数200通り + 格子 + 1台8本 + 平行リンク |
| ポート名の位置 | 上下左右・斜め・逆向きで「自分の機器側に付く」ことを固定 |
| 取り込み ⇄ 書き出し | 書き出したものを取り込み直して値が変わらないこと |
| マイグレーション | upgrade / downgrade の往復 |
| 対処漏れ | 「書いた」と「入れた」が別扱いであること、版が変われば差し戻ること |
| 画面が開くこと | 引数の要らない GET を全部叩いて、どれも開くこと |
| 生成した Config | 出したものを自分の読み手で読み戻して、同じ機種として読めること |

テストで担保できていないもの（人が見るしかない部分）:

- 図の美しさ（被っていないことは機械で見られるが、読みやすいかは別）
- 実機コマンドが本当に正しいか（書式は検証できるが、意図どおり動くかは投入して確認）
- 日本語フォントでの文字幅（環境依存。Windows / Mac で見え方が変わる可能性）

## 4. 決めてほしいこと（今は仮で置いてあるもの）

| 項目 | 今の既定 | 論点 |
|---|---|---|
| ポート名の表記 | 略記（`Gi1/0/24`） | 現場に合わせて「番号だけ」に倒すか |
| ポート名の向き | 横書き | 好みが分かれるところ。設定は端末ごとに保存されます |
| メニューの折り畳み | 使える状態 | 要らなければ外す。区切り線だけで足りるかもしれない |
| 対向の簡易表示 | 出す | 拠点をまたぐ回線が多いと簡易ノードが増える。多すぎるなら集約する |
| トランク経由の VLAN | 「載っている」に含める | 通過するだけの VLAN を含めるか、定義がある機器だけにするか |

上の3つは実際に何度か使ってみないと決められない類のものです。しばらく使って、
違和感があったところを教えてください。

## 5. 今は無いもの（把握しておいてほしい制約）

| 無いもの | 影響 | 補い方 |
|---|---|---|
| 認証・認可 | 1.1 のとおり | 当面は `127.0.0.1` のまま自分だけで使う |
| SSH での自動収集 | Config は手動アップロード | 月次で手動収集。定期取得は別の仕組みが要る |
| 変更者の記録 | 「誰が」が埋まらない | 認証が入って初めて意味を持つ |
| 洗い直しの自動実行 | 押し忘れると古い数字を見る | 月次の作業手順に入れる |
| レイヤ切替の中身 | 物理はケーブル、L2 は VLAN 結線、L3 はルーター/IP、論理はトンネル | デモデータでも切り替えを試せる |
| 機器への投入 | 生成するだけ | 意図的にそうしています（1.1 の解決前に投入機能は持たせない方がよい） |

レイヤ切替は、物理 / L2 / L3 / 論理で描く内容が違います。 VLAN やトンネルが
無い環境では空の図になるので、そのときは物理構成を見てください。

## 6. 人に見せるときの順番（デモの筋道）

`python -m scripts.seed` で、台帳・結線・VLAN に加えて本社6台の Config も
入ります（`backend/scripts/demo_configs/`）。Cisco 4台に加えて、
Juniper（edge-rt-01）と FortiGate（fw-01）も入れてあるので、
1つのベンダーだけで動いているようには見えません。あわせて、型番ごとの期限、CVE と
その該当、弱点への対処、設定変更用のテンプレート、更改の検討案が1本入ります
（`backend/scripts/demo_reference/`）。入れたあとは、点検・L3・Config 計画・
対処手順・テンプレート・シナリオの画面が、どれも中身のある状態で開きます。
台帳だけ入れても、この道具の値打ちが出るところが空のままになるためです。

メーカー資料（マニュアル）だけは空のままです。実在しない資料の情報を作って
入れることはしていません。

機能を順番に説明すると伝わりません。困りごとから入る方が早いです。

1. ダッシュボード … 「保守切れが何台あるか、今すぐ言えますか」
2. 機器一覧 → 詳細 … Excel 台帳との違いは、期限が自動で色分けされること
3. Config の取り込み … ファイルを放り込むと台帳と結線が立ち上がる
4. トポロジー図 … 拠点で絞る、VLAN で絞る、SVG で出す
5. 更改支援 … 年度別の台数と、止めたときに落ちる機器の名前
6. 対処状況 … 未対応が何件か。「対処を書いた」と「入れた」が別であること
7. Config 計画 … 差分は将来フルに収束することを検証してから出す

7 が一番効きます。 「差分を機械が作って、正しいことを機械が確かめている」は
他のツールにあまり無い部分です。

見せるときの注意:

- プレビュー環境（Vercel）はデモ専用です。実機の情報は入れないでください
- デモデータには、わざと次のものを仕込んであります。「見つけられる」ことを
  見せる材料に使えます

  - トランクの許可漏れ … acc-sw-01 の上流だけ VLAN 40（無線）を通していない。
    同じ機器の AP 用ポートは 40 を通しているので、無線だけが上に届かない
  - ネイティブ VLAN の不一致 … core-sw-02 と wlc-01 の間で 999 と 1
  - EoL 切れ
  - core-sw-01 だけログの送り先が違う（他の3台は同じ先）。1台だけ設定が違う、
    という現場でいちばん多い事故がそのまま出ます
  - VLAN 30 の台帳の区画（192.168.30.0/24）と、実機のアドレス（10.0.0.x）が違う
  - VLAN 20 は実機にあるのに台帳に無い

## 7. 次に作るなら、という候補

優先順です。1 と 2 は運用に入るなら実質必須です。

1. 認証（1.1）
2. ~~バックアップの自動化~~ … 間隔と世代を決めて裏で取り、開けることまで
   確かめる形で対応済み。戻す手順の定着（実際に戻して試す）は人の作業
3. ~~レイヤ切替の中身（L2 = VLAN 単位、L3 = セグメント単位で描き分ける）~~ ✅
4. ~~洗い直しの定期実行~~ … 裏で回し、増えた件数を画面に出す形で対応済み。
   外への通知（メール等）は認証が入ってから
5. ~~投入後の突合の自動化（取り込み → 差分ゼロ確認までを1操作に）~~ … `POST /config-plans/{id}/verify` で対応済み
6. Config の SSH 自動収集（認証と監査が入ってから。それ以前に作ると危ない）
7. 起動の作り込み。いまは配布物の中のバッチから、窓を1つ出して動かす形。
   ここを2方向へ伸ばす。

   - 手元の端末: 単体の実行ファイル（PyInstaller）にして、アイコン付きで
     タスクバーに並ぶ形にする。署名が無いと SmartScreen に一度止められるので、
     社内配布の手順とあわせて決める
   - サーバー: 常時起動。Linux は `netvision.service`（systemd）が既にある。
     Windows Server なら サービス登録（NSSM 等）を用意する。どちらも
     「窓を閉じたら止まる」形ではいけないので、起動役とは別の道にする
