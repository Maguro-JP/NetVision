# AI・読み取りの精度

## 増設の文から「つなぐ先」を読む（askplan、2026-09-26 JST）

- 方式: 規則ベース。台帳の hostname・管理ID・機器名が文に出てきたものを当てる。LLM は使わない。
- 問題: 部分一致だったため、core-sw-10 と書くと core-sw-1 にも当たり、台帳の並び次第で
  別の機器を黙って選んでいた。
- 対策: 前後が名前の文字（英数字・ハイフン・下線・続きのあるドット）でないときだけ当てる。
- 評価: 似た名前を並べた 16 文（`tests/test_askplan.py` の
  `test_a_name_inside_another_name_is_not_mistaken`）。直す前 7/16、直した後 16/16。
  この組は不具合に寄せて作ったもので、実際に利用者が書く文での正解率ではない。
  実際の文を集められたら、その正解率を別に測る。
- LLM を使う機能の精度は、この環境に LLM が無いため測れていない（未測定）。

## Config のベンダー判定（detect_vendor、2026-09-27 JST）

- 方式: 規則ベース（`app/services/configparse/__init__.py` の `detect_vendor`）。
- 測り方: 手元の見本 13 本（`backend/tests/fixtures/`）それぞれについて、全文での判定を正として、
  先頭 40 行・末尾 40 行・途中 40 行・先頭にプロンプト行（`sw# show running-config`）を足したもの・
  改行を CRLF にしたもの、の 5 通りを判定した。
- 結果: 58/65 が全文と同じ。外れた 7 件はすべて「不明（unknown）」で、別のベンダーに取り違えたものは 0 件。
  外れたのは途中や末尾だけの断片（IOS 3、FortiOS 1、PAN-OS の XML 3）。
- 判断: 断片で「不明」を返し、利用者にベンダーを選ばせるのは安全側なので、変えていない。
  取り違え（誤判定）が出たら、そのときに規則を見直す。
