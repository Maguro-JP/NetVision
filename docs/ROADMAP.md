# NetVision ロードマップ

目的は「ネットワークの構成・保守・バージョンを1か所で把握できる状態」を作ることです。
価値が早く出る順に段階を切っています。

## フェーズ1: インベントリ + 保守期限管理 ✅ 実装済み

- 機器 / 拠点 / 保守契約のデータモデルと CRUD API
- 保守期限・EoS・EoL の残日数計算と重要度判定
- ダッシュボード、機器一覧（検索・絞り込み）、機器詳細
- 単体でも Excel 台帳を置き換えられる状態

## フェーズ2: Config 取り込みとパース

- Config のアップロード（手動）と収集（SSH / SCP / TFTP）
- パースして自動抽出
  - ホスト名、OS バージョン、型番、シリアル → **インベントリの自動更新**
  - インターフェース、VLAN、IP アドレス、ルーティング
  - LLDP / CDP ネイバー → **物理結線の推定**
- Config のバージョン履歴と差分表示（変更追跡・監査証跡）

技術候補: `ciscoconfparse2` / `ntc-templates`（TextFSM）/ `napalm`。
ベンダー差異はパーサをプラグイン化して吸収する。

### 設計メモ
Config パース結果は「観測値」、手入力データは「台帳値」として分けて保持し、
食い違いを検出できるようにする（例: 台帳の OS バージョンが実機と違う）。
自動で上書きせず、差分を提示して人が承認する方式にする。

## フェーズ3: トポロジ可視化エディタ

- フェーズ2 で推定した結線を初期配置として自動生成（elkjs で自動レイアウト）
- 人が手でノード配置・線の引き直し・グルーピングをして図を仕上げる
  - 配置は永続化し、機器の追加時も既存レイアウトを壊さない
- レイヤ別ビュー: 物理 / L2 (VLAN) / L3 (セグメント) / 論理
- ノードクリックでインベントリ・保守期限・脆弱性情報へ遷移
- 図の PNG / SVG エクスポート（設計書への貼り付け用）

技術候補: React Flow + elkjs。

## フェーズ4: 脆弱性情報の管理

- 「ベンダー + 型番 + 稼働バージョン」から該当 CVE を自動マッチング
- データソース: NIST NVD API、各ベンダー PSIRT（Cisco PSIRT openVuln など）
- **閉域環境を前提に、脆弱性データはオフラインインポート可能にする**
  （定期的に JSON を持ち込んで取り込む導線を用意する）
- 影響機器の一覧、推奨アップグレード先バージョンの管理

## フェーズ5: 更改支援

- 「今後N年で保守切れ・EoL を迎える機器」を年度別に集計
- 更改対象の影響範囲をトポロジ上でハイライト（その機器配下のノード）
- 更改案件のグルーピングと予算年度への割当、概算費用の積み上げ
- CSV / Excel エクスポート（稟議・見積依頼用）

## 横断的に必要になるもの

- 認証・認可（まずはローカルアカウント、将来的に LDAP / OIDC）
- 変更履歴（誰がいつ何を変えたか）
- CSV インポート（既存 Excel 台帳からの移行導線）— 導入障壁を下げる意味で優先度は高い
- 期限アラートのメール / Webhook 通知
