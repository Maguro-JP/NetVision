# プレビュー環境（Vercel）

PR ごとに実際の画面を触って確認するための環境です。

> プレビューは画面確認用です。実機の情報を入れる導入テストは、自分のPCの
> 1台完結モード（[GETTING_STARTED.md](GETTING_STARTED.md)）で行ってください。
> チームで共有する段階で Docker Compose に載せます。

## 何が動くか

| 層 | プレビューでの扱い |
|---|---|
| フロントエンド | Vite でビルドした静的ファイルを配信 |
| バックエンド | `api/index.py` から FastAPI をサーバーレス関数として起動 |
| データベース | 既定は一時領域の SQLite（データは永続しません） |
| 資料ファイル | `/tmp` 配下（永続しません） |

デモモードのときは画面上部に「データは永続しません」と常時表示されます。
黙って消えると事故のもとなので、隠さず出しています。

## セットアップ

1. Vercel でこのリポジトリを Import する
2. Framework Preset は Other（`vercel.json` の設定が使われます）
3. そのままデプロイすると、DB 不要のデモモードで立ち上がります

環境変数の設定は不要です。初回アクセス時にスキーマを最新にし、デモデータを流し込みます。

### データを永続させたい場合

Postgres（Neon など）を用意して、環境変数を設定します。

| 変数 | 値 |
|---|---|
| `NETVISION_DATABASE_URL` | `postgresql+psycopg://...` |

この場合デモモードは自動的に無効になります。空の DB は起動時に表ができます。
すでに中身がある DB に差分があるときは、画面の「表の更新」で控えを取ってから当てます。
Vercel のサーバーレスには `pg_dump` が無いので、Postgres を繋いだプレビューでは
そのページから更新できません。プレビューはデモ用 SQLite のままにしてください。

## PR ごとのプレビュー

Vercel にリポジトリを接続すると、PR を作るたびに固有の URL でプレビューが作られます。
本番相当の URL は、**Production の Branch Tracking が指す枝**（このリポジトリでは `main`）へ
push / マージしたときに更新されます。

Branch Tracking を変えただけでは、いま Current になっているデプロイは変わりません。
変えたあとに `main` へ何か push するか、Deployments から `main` のデプロイを
Promote / Redeploy してください。

```
PR を作る → Vercel が自動でビルド → PR にプレビュー URL が付く → 画面で確認
→ Merge して main に入る → 本番 URL が更新される
```

## 最初のデプロイで確認すること

サーバーレスのリライトが元のパスを関数へ渡すかは環境の挙動に依存します。
渡っていない場合、素の 404 だと原因が分かりにくいので、
何が起きているかを名指しで返すようにしてあります。

```bash
curl https://<プレビューURL>/health
# => {"status":"ok"}

curl https://<プレビューURL>/api/v1/meta
# => {"demo_mode":true,...}
```

`/api/v1/meta` が次のように返る場合は、`vercel.json` の `rewrites` を見直してください。

```json
{ "detail": "リライトで元のパスが関数に渡っていません...", "hint": "path_not_forwarded" }
```

## 制約

- データは永続しません。 サーバーレスの実行単位ごとに一時領域が分かれるため、
  書き込んだ内容が次のアクセスで見えないことがあります
- ファイルのアップロード（ベンダー資料）は動きますが、同じ理由で消えます
- 実機の構成情報・シリアル・IP などは入れないでください。
  外部に置く前提の環境なので、閉域運用の前提が崩れます
