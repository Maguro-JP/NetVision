# 良い図とは何か

配置のレシピ（上にセンター、右に営業所）は既に書いてある。それは並べ方であって、良い図の定義ではない。

良い図は、印刷してラックの前で指差せる資料である。PowerPoint に貼っても、誰が上位か・どこが冗長か・どのポートかが残る。

## 一目で分かること

- 誰が上流か（上が上位。同じ役割は同じ高さ）
- どこが冗長か（2台は横並び。縦に積むと主系／予備に見える）
- どのケーブルの、どのポートか（名前は線の真ん中ではなく、その箱の折れ曲がり）
- 物理だけか、論理だけか（OSPF を物理ケーブル図に混ぜない）

## 線の引き方

現場の Visio で図が読めるのは、箱の色よりコネクタの扱いである。

- 直角だけ。斜めは出さない。箱を貫かない
- ハブ側で線を重ねてから、等間隔で扇状に開く
- ポート名はコネクタの端（その機器の外）
- 避けられない交差は弧のジャンプではなく隙間
- 人が置いた位置は、見るだけでは動かない。自動で線を引き直さない
- A3 に刷って読める。画面のツールバーは資料ではない

## 悪い図

- 放射状・力学モデル。上下が無く、見るたびに箱が飛ぶ
- 斜めのフルメッシュ。線が髪の毛になる
- ポート名が線の中央。「左が上位」といった規則で補う
- 空の何千ピクセル。対向の2台目を1台に折りたたんで冗長が消える
- グラフエディタの画面そのものが「構成図」になっている

## 見本の役割

`proposed-optimal.png` は、上の見た目の手置き見本である。製品の出力ではない。
機器の数を増やす話ではなく、資料として読める線と段の話である。これが読めないなら、コードの話はまだ早い。

`netvision-kansai.svg` は、いま製品が出している図である。白い箱が数個で、対向の2台目は折りたたまれている。まだ資料ではない。

## third-party の判定

再利用できるもの（Wikimedia）だけを対象にしている。Cisco CVD の図は学習には使えるが、
こちらへコピーできないのでリンクに留める。

| ファイル | 判定 | 理由 |
|---|---|---|
| `flat-vs-hierarchy.png` | 良い（説明用） | フラットが破綻し、階層が読めることを示している |
| `hierarchical-tree.jpeg` | 半分良い | 段はある。斜めだとポート順が置けない |
| `sample-network.svg` | 半分良い | 拠点の話には近い。線が斜めだと交差が増える |
| `ospf-cisco-style.svg` | 良い（L3 専用） | 論理図として別枚。物理に混ぜない見本 |
| `fast-ethernet-logical.svg` | 良い（論理の説明） | 物理ケーブル図ではない |
| `fat-tree.svg` | この製品では使わない | DC 向け。支社 WAN の運用図ではない |
| `tree-radial.png` | 悪い | 上下が無い。反例 |
| `network-topologies.svg` | 教科書 | バス／リング／スターの説明。運用図ではない |
| `textbook-topologies.png` | 教科書 | 同上 |
