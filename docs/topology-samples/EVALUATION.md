# 公開されている学習用構成図の評価

再利用できるもの（Wikimedia）だけを対象にしている。Cisco CVD の図は学習には使えるが、
こちらへコピーできないのでリンクに留める。

判定の物差し（NetVision が出すべき図と同じ）:

1. 段が読める（同じ役割が同じ高さ）
2. 上位が上、冗長は横並び
3. 線は縦横。箱を貫かない。束は等間隔
4. ポート名は箱の隣（中央に「左が上位」規則を置かない）
5. 物理と論理を1枚に混ぜない
6. 放射状・斜めのフルメッシュは運用図として悪い

## third-party の判定

| ファイル | 判定 | 理由 |
|---|---|---|
| `flat-vs-hierarchy.png` | 良い（説明用） | フラットが破綻し、階層が読めることを示している |
| `hierarchical-tree.jpeg` | 半分良い | 段はある。放射に近いとポート順が置けない |
| `sample-network.svg` | 半分良い | 拠点の話には近い。線が斜めだと交差が増える |
| `ospf-cisco-style.svg` | 良い（L3 専用） | 論理図として別枚。物理に混ぜない見本 |
| `fast-ethernet-logical.svg` | 良い（論理の説明） | 物理ケーブル図ではない |
| `fat-tree.svg` | この製品では使わない | DC 向け。支社 WAN の運用図ではない |
| `tree-radial.png` | 悪い | 上下が無い。反例 |
| `network-topologies.svg` | 教科書 | バス／リング／スターの説明。運用図ではない |
| `textbook-topologies.png` | 教科書 | 同上 |

## NetVision が実装すべき図

拠点で絞った **物理構成** が本命。形は `proposed-optimal.png`。

- センターは真上。冗長なら同じ段に横並び
- 自拠点は縦の背骨
- 配下拠点は右の列
- 線は箱の辺から縦横。斜めは出さない

画面の好み（略記・シンプル）は、この正解の上に乗せる。

## 構築後の再評価

`netvision-kansai.svg` は、関西支社で絞った自動配置＋SVG 書き出しです。

直す前: センターが営業所と同じ右列の下にあり、線は斜め。悪い図。
直したあと: センターが上、支社が縦、営業所が右、線は縦横。合格。

大規模ではコア／メトロ／アクセスの段を機器に付け、拠点や段を枠で囲める。
枠・種別・線の色は人が変えられる。
