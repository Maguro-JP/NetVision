# 重さの決め方

重さは 3 つです。重さで、いつ直すかと、修正版を出すかが決まります。迷ったら重い側にします。

出どころ: 重さを影響・頻度・回避で決める考えは、mohitagw15856/pm-claude-skills の `bug-triage-pack`（MIT）の要点です（文は写していません）。
致命的に当たる物の並びは、Donchitos/Claude-Code-Game-Studios の `hotfix`（MIT）の重さの段を参考にしました。

| 重さ | 当たる物 | 扱い |
|---|---|---|
| 致命的 | クラッシュ、起動しない、操作不能、データの破損や消失、情報の漏洩、悪用できる脆弱性 | 今の作業を止めて、修正版を即出す |
| 重い | 主な機能が動かない。回避はできる | その日の開発の最初に直す |
| 軽い | 見た目、文言、まれな場面 | 次の PR にまとめる |

## 決める順

上から順に見て、最初に当たった重さにします。

1. 使う人のデータ、鍵、個人情報に害がある（壊れる、消える、外に出る、他人に読める）なら、致命的です
2. 使えない（落ちる、起動しない、固まる、入力を受け付けない）なら、致命的です
3. 主な機能が期待と違う動きをする。別の手順で同じことはできるなら、重いです
4. 見た目、文言、まれな場面だけなら、軽いです
5. どれか分からないなら、重い側にします。調べて軽いと分かったら、帳簿の重さを書き換えます

見るのは、影響（何が失われるか）、頻度（誰に、どのくらい起きるか）、回避（別の手順があるか）の 3 つです。
影響が 1 か 2 に当たる物は、頻度が低くても致命的のままにします。まれにしか起きない破損は、起きたときに戻せないためです。

## 例

| 物 | 致命的 | 重い | 軽い |
|---|---|---|---|
| アプリ（ウィンドウで開く物） | 起動でウィンドウが出ない。保存で設定のファイルが壊れる。操作の途中で落ちる。画面が固まって閉じるしかない | 検索が効かない（一覧からは探せる）。書き出しが失敗する（コピーはできる） | ボタンの文言が古い。余白がずれる |
| ゲーム | 開始で落ちる。セーブが消える。先に進めなくなる | 一部の面で音が出ない。設定が保存されない（毎回選び直せる） | 表示が 1 フレームずれる。誤字 |
| ツール、スクリプト | 例外で止まる。入力のファイルを壊す。鍵をログに出す | 一部のオプションが効かない（別のオプションで同じことができる） | ヘルプの文言。出力の桁ぞろえ |
| ライブラリ | import で落ちる。黙って違う値を返す（使う側のデータが壊れる） | 一部の引数で例外になる（別の呼び方がある） | 文書の誤り。警告の文言 |
| Ciel のスキルとフック | フックが全部のツール呼び出しを止める。配ったテストが配った先の全部で落ちる。鍵や非公開の名前を出す | フックが偽の差し戻しをする（1 行で通せる）。スクリプトの一部が動かない | 文言、表記 |

## 重さと、テストや Actions の失敗

テストや Actions が「落ちた」は、アプリが落ちたのとは違います。何が落ちたかを読んでから重さを決めます。

- main ブランチで落ちているテストが、クラッシュや破損を見ている物なら、致命的です
- 主な機能のテストなら重い、文言や見た目のテストなら軽いです
- テストそのものの誤り（テストの書き方、環境）でも、main ブランチが落ちたままだと次の修正版を出せません。重いにします

## 黙って違う結果を出す物

落ちないバグの方が、落ちるバグより害が大きいことがあります。保存したつもりで保存されていない、
計算の結果が違う、別の人のデータが出る、のように、使う人が気づかずに害を受ける物は、致命的にします。
