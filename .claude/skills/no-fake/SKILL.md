# 見せかけを作らない・動かして見せる・壊さない

ユーザーの指摘は 5 つ。このスキルとフックで抑える。

1. コーディングが出来ない
2. 出来ているように見せるだけ
3. バグも放置
4. わかっていてわざと壊す
5. AI の悪いところを徹底的に抑制して。限りないから、常に改善して

根は 1 つで、動く物を作ることより、通ったと見せることを目的にしている。関数の名前だけ置く。例外を握りつぶしてエラーを消す。
落ちるテストは消すか弱める。検査は黙らせる。そして「できました」と言う。
直し方も 1 つで、動かした出力で示す。書けていない所、消した物、弱めた検査は、隠さずに 1 行で書く。

## 3 本の柱

| 柱 | 場面 | すること | しないこと | 機械の見張り |
|---|---|---|---|---|
| A 見せかけを作らない | コードやテストを書くとき | 本物の処理を書き切る。書けない所は、書けていないと返答に書く | 置き場のままの実装、握りつぶし、偽のデータと振り、テストの見せかけ、配線されていない物 | `fake_scan.py`、`fake_nudge.py`、`fake_gate.py` |
| B 動かして見せる | コードを変えたターン | 変えたコードを、そのターンで実際に動かす。テストの無い所は、落ちるテストを先に書く | 読んだだけ、書いただけで終える | `fake_gate.py` |
| C 壊さない | 変える前、消すとき、検査を変えるとき | 変える前の状態を測る。消した物を数える。検査を弱めない。気づいた不具合を黙って残さない | 通っていたテストを落としたまま終える。頼まれていない削除。検査を黙らせて通す | `baseline.py`、`removed.py`、`fake_gate.py`、precheck |

## A 見せかけを作らない

出来ているように見せるだけの形は、5 種類ある。形の全部と、拾わない物は `references/patterns.md`。

| 種類 | 形の例 | 代わりにすること |
|---|---|---|
| 置き場のままの実装 | `pass` だけ・`...` だけ・`raise NotImplementedError`・固定の値を返すだけの関数。`TODO`、仮、ダミー、`placeholder`、`stub` の語。「残りは同じ」で省いたコード | 本物の処理を書く。まだ書かないなら、関数を足さない。名前が check、validate、verify、is_、has_ の関数は、見ないで True を返さない |
| 握りつぶし | 中身の無い except や catch、`except Exception: pass`、`.catch(() => {})`、新しく足した `\|\| true` と `2>/dev/null` | 記録するか、捕まえる型を絞るか、投げ直す。捨ててよいなら、理由を同じ行のコメントに書く |
| 偽のデータと振り | 本物の処理の代わりに固定の配列・乱数・sleep を返す。条件なしに「成功しました」を出す。テストのときだけ別の値を返す分岐 | 本物の処理を呼ぶ。外の物が要るなら、要ると書いて止まる。テストと本番で同じ道を通す |
| テストの見せかけ | assert の無いテスト、`assert True`、期待値を出力に合わせて書き換える、`skip`・`xfail`・`only`・`todo` を足す、テストを消す、対象そのものをモックで置き換える、スナップショットの一括更新 | 落ちたテストは、コードの側を直す。テストの側を変えるのは、仕様が変わったときだけで、理由を書く |
| 配線されていない物 | 定義しただけでどこからも呼ばれない関数・部品・ハンドラ、ハンドラの無いボタン、登録されていないルート、読む所の無い設定 | 入口から呼ぶ所までつなぎ、入口から動かして見る |

1. 書く前に、何を動かせば出来たと言えるかを 1 行で決める（verify-before-done の 1）
2. 書いたら `fake_scan.py --diff <base>` を回す。重大は直す。注意は、残す理由があるものだけ残す
3. 書けなかった所を残すときは、返答に `❕ 見せかけ: <何>（残っている物と理由）` を 1 行書く。黙って置き場を残さない
4. 意図して残す形（終了の途中の握りつぶしなど）は、その行に `no-fake: ignore（理由）` を書く

## B 動かして見せる

コーディングが出来ない、と言われるのは、動かしていない物を出すから。

1. 変えたコードは、そのターンで実際に動かす。テストを流すか、起動して入力と出力を見る。読んだだけ、書いただけで終えない
2. テストの無い所を変えるときは、落ちるテストを先に書き、落ちるのを見てから直す。直したあとに通るのを見る
3. UI は実際に開いて見る。押して、答えが返るのを見る（ui-design の歩き方）
4. 動かせなかった物は、返答に「動かしていない」と理由を書く（例: `❕ 疑い: 起動は動かしていない。この環境に画面が無い`）
5. 長いテストは裏で動かし、出力をファイルに書く（background-first）。結果を読まずに「通った」と言わない

## C 壊さない

わかっていてわざと壊す、と言われるのは、通っていた物を落とし、要る物を消し、検査を黙らせるから。

1. 変える前の状態を測る。変える前に `baseline.py save` でテストの結果（通った物・落ちた物の名前）を記録する。
   変えたあとに `baseline.py compare` を回し、通っていたのに落ちた物が出たら、戻すか直す。落ちたまま終えない
2. 消した物を数える。`removed.py --diff <base>` が、消えた関数・クラス・export・テスト・ファイル・設定・UI の要素を一覧にする。
   頼まれていない削除は戻す。消すときは、返答に `❕ 消した: <何>（理由。頼まれた、または置き換え先）` を書く
3. 検査を弱めない。テスト・lint・型・CI・フック・ゲートを緩める変更（skip、しきい値を下げる、`--no-verify`、`continue-on-error`、
   `eslint-disable`、`# type: ignore`、`noqa` を新しく足す、フックの登録を消す）は、頼まれたときだけ。
   足したら、返答に `❕ 弱めた: <何>（理由）` を書く
4. 自分で気づいた不具合を、黙って残して終えない。その場で直すか、bug-first の帳簿（`docs/reports/bugs.md`）に書く

## 返答に書く行

| 行 | いつ |
|---|---|
| `❕ 見せかけ: <何>（残っている物と理由）` | 重大の形（握りつぶし、偽の検査、省略、いつも通るテスト）を、このターンで足して残すとき |
| `❕ 弱めた: <何>（理由）` | テストを飛ばした・assert を減らした・期待値を書き換えた・スナップショットを更新した・検査を黙らせた・しきい値を緩めたとき |
| `❕ 消した: <何>（理由。頼まれた、または置き換え先）` | 関数・クラス・ファイル・テストを消したとき |
| 「動かしていない」と理由 | コードのファイルを変えたのに、そのターンで動かせなかったとき |

行を書けば通るが、書くのは事実だけ。直せる物は、行を書く前に直す。

## スクリプト

```bash
python3 .claude/skills/no-fake/scripts/fake_scan.py .                  # リポジトリ全体の形の一覧（月に 1 回の整理整頓、公開の前）
python3 .claude/skills/no-fake/scripts/fake_scan.py . --diff origin/main  # 分かれ目から後に足した行と消した行だけ（precheck が回す）
python3 .claude/skills/no-fake/scripts/removed.py . --diff origin/main    # 消えた関数・クラス・export・テスト・ファイル
python3 .claude/skills/no-fake/scripts/baseline.py save                   # 変える前のテストの結果を記録する
python3 .claude/skills/no-fake/scripts/baseline.py compare                # 通っていたのに落ちた物を出す
python3 .claude/skills/no-fake/scripts/fake_scan.py --stats --days 7      # この 7 日に拾った数（種類ごと）
```

- `fake_scan.py` は重大があれば終了コード 1。最後の行は `見せかけの確認: 重大 n / 注意 n`
- `baseline.py` が読むのは、pytest と unittest と npm test の出力（jest、vitest、mocha、TAP の形）。テストの無いリポジトリでは何も出さない。
  記録は `~/.claude/state/no-fake/` に置き、リポジトリには置かない
- 抑止は、行の末尾の `no-fake: ignore（理由）`、ファイルの先頭の `no-fake: ignore-file（理由）`、
  消した物はコミットメッセージの `no-fake: ignore <パスか名前>（理由）`
- 配った先のリポジトリでは、`.claude/skills/` の中を見ない。そこにあるのはスキルの元のリポジトリのコピーで、直すのは元の側。
  コピーの中の形で、配った先の検査と返答を止めないため。スキルのテストを `baseline.py` が流すのも、元のリポジトリだけ

## フック

| 何 | いつ | すること | 止めるか |
|---|---|---|---|
| `hooks/fake_nudge.py` | PostToolUse（Edit、Write、MultiEdit） | 書いた中身に重大の形があれば、何行目のどの形かを 1 行で知らせる。この編集で足した行だけを見る | 止めない |
| `hooks/fake_gate.py` | Stop | このターンの編集に、重大の形が残っている・テストを消したか弱めた・関数やファイルを消した、のどれかがあり、返答に対応する行が無いとき。コードのファイルを変えたのに、変えたあとに 1 回も動かさず、「動かしていない」とも書いていないとき | 止める。直すか、上の表の行を 1 行足すと通る |
| precheck の `no-fake` の段 | PR を作る前、マージの前 | `fake_scan.py --diff <base>` を回す。重大で NG、注意は数だけ出す | 重大で止める |

- `NO_FAKE_OFF=1` で 2 本とも止まる（ユーザーが自分の手で入れる）
- 差し戻しの文は 1 行。差し戻されたら、足りない 1 行だけを足す。`stop_hook_active` が真なら通す
- 人の発言・通知・差し戻しの見分けは、common-sense の `_cs.py` を使う。common-sense が無いリポジトリでは、`fake_gate.py` は黙って通す
- ユーザーが置き場や削除を頼んだターン（一言に「骨組み」「スタブ」「あとで実装」「消して」「削除」がある）は、その形では差し戻さない
- `fake_nudge.py` は、code-check の `code_nudge.py` が出す物（構文、脆弱性の型、情報の扱い）を出さない。テストのファイルの中の文字列の見本と、
  このスキルの表には当てない
- テスト: `scripts/test_fake_scan.py`、`scripts/test_removed.py`、`scripts/test_baseline.py`、`scripts/test_hooks.py`

## 常に改善する（数え方）

AI の悪いところは限りが無いので、拾った数を残し、週 1 回見て形を足す。

- フックと `fake_scan.py` は、拾った数を種類ごとに 1 行ずつ `~/.claude/state/no-fake/metrics.jsonl` に足す。
  1 行は `ts`・`session`・`src`（nudge、gate、scan）・`kind`（置き場、省略、偽の検査、握りつぶし、偽のデータ、テスト、配線、弱めた、消した、動かしていない）・`sev`・`n`、
  gate の行には `blocked`（差し戻したか）
- 数えるのは `fake_scan.py --stats --days 7`。週 1 回の skill-upkeep は、種類ごとの数と、差し戻しの数を週報に写す
- 同じ種類が 2 週続けて増えたら、その種類の断片を読み、形を `references/patterns.md` と `fake_scan.py` に足す。
  足すときは、テストに拾う見本と拾わない見本を組で足し、リポジトリ全体と実際の会話の記録に当てて、偽の当たりを見る
- 差し戻しが偽だった形（行を書かせただけで、直す物が無かった）は、拾わない側に足す。偽の差し戻しは、ユーザーの時間を使う
- ユーザーに新しい形を指摘されたら、その場で表とテストに足し、lessons に書く

## 使わないとき

- 完了の語（できました、通りました）の根拠の照合と、編集のあとの読み直し（verify-before-done）
- バグの帳簿と、バグ修正の優先（bug-first）
- 構文・未定義・脆弱性・情報の扱いの検査（code-check）
- 推測の語と、調べずに済ませること（common-sense）
- 文書だけの変更、調査だけで終わる作業

## 他のスキルとの関係

重なる決まりは、docs/GUIDELINES.md の 10 に、どちらに従うかを書いてある。

- verify-before-done の `done_check.py` は、完了の語を、ツールの出力と照合する。`reread_check.py` は、編集のあとの読み直しか実行を求める。
  このスキルの `fake_gate.py` は、語ではなく編集の中身（足した形、消した物）と、コードを変えたあとの実行を見る
- code-check は、落ちる・穴がある・漏れる形を見る。このスキルは、動くように見えて中身が無い形を見る。
  `except: pass` と `--no-verify` は code-check でも注意で出るが、新しく足した物を重大にするのはこのスキル
- 「頼まれていない改変を混ぜない」は、足す側の決まり。このスキルの C は、消す側と弱める側を見る
- bug-first は、見つけたバグを帳簿に書いて先に直す。このスキルは、バグを隠す形（握りつぶし、テストを弱める）を作らせない
