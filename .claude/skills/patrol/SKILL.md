# 見回り

long-dev を回しているリポジトリは、それぞれ別のセッションで動く。1つずつ見に行くと、
毎回同じ手順を組み立てることになる。ここで1回にまとめる。

## 手順

1. `list_triggers` で有効な Routine を出し、名前が `long-dev（<repo>）` のものから、リポジトリと結びつけ先のセッション（`persistent_session_id`）、次の起床（`next_run_at`）を取る
2. GitHub 側をまとめて見る

```
.claude/skills/patrol/scripts/patrol.sh <owner/repo> <owner/repo> ...
```

3. セッション側を見る。結びつけ先ごとに `get_session` で `session_status`（RUNNING / IDLE）、`task_summary` か `post_turn_summary`、`context_usage.used_tokens`、`rate_limit_info.status` を取る
4. IDLE のセッションは、次の起床があるかを `list_triggers`（非定期・有効）で見る。無ければ止まっている
5. 1つの表にして出す

```
| リポジトリ | セッション | 次の起床 | 最後のコミット | 開いている PR | 答え待ち | 気になること |
```

「気になること」に書くのは、止まっている・翌朝まで起床が無い・答え待ちが増えた・Actions が落ちている・利用枠が警告、のどれか。無ければ空欄。

## 止まっているかの判定

| 見えたもの | 判定 |
|---|---|
| RUNNING | 回っている |
| IDLE で、数時間以内の起床がある | 回っている（周の間） |
| IDLE で、起床が翌朝の Routine だけ | 止まっている。auto-dev の「次の起床を予約してから終える」が守られていない。一回きりの Routine で「続けて。周の終わりに次の起床を予約する」と送る |
| 最後のコミットが半日以上前で RUNNING | 詰まっている可能性。`task_summary` を見て、同じことを繰り返していれば止めて送り直す |

## 出さないもの

- 周ごとの経過。会話に出すのは表と「気になること」だけ
- 費用の数字は、聞かれたときだけ答える。文書には書かない（public のリポジトリに残る）

## 他のスキルとの関係

- 答え待ちに答える: `pending`
- Routine を作る・送る・掃除する: `scheduler`
- 枝と PR の掃除: `tidy`
