# 失敗の記録

私はセッションをまたいで記憶を持たない。今日の失敗は、次のセッションの私には無い。
だから記録が要る。ただし書くだけでは前と同じで、読まれなければ意味がない。
読む側はフックに任せ、書く側をこのスキルが決める。

## 記録する条件

次のどれかに当たったら、作業を続ける前に1件足す。

- 相手から「また」「前も」「やらかした」と言われた
- 自分の判定が誤っていたと、事実で分かった
- 不具合の原因が、自分の見落としや思い込みだった

コードの不具合そのものは書かない。書くのは「私の判定がどう誤ったか」。

## 書き方

`.claude/skills/lessons/LESSONS.md` の先頭に足す。1件は見出しと4行。

```
## YYYY-MM-DD 何をしたか（1行）
場面: 索引になる短い名詞。複数ならカンマ区切り
起きたこと: 事実。数字とファイル名を入れる
判定の誤り: どこで何をどう間違えたか
次から: 次に同じ場面で、最初にやること。コマンドがあればコマンド
```

「次から」は1行にする。フックはこの行だけを差し込むので、長いと全部が重くなる。

一般論は書かない。「確認を怠らない」は次からの行動にならない。
「`git ls-remote --heads` で見る」なら行動になる。

## 読まれ方

`.claude/hooks/lessons.sh` がセッションの開始・再開・圧縮後に、
`場面` と `次から` の行を差し込む。全文は読まない。
同じ場面の作業に入るとき、差し込まれた行を見て、そこに書かれた最初の一手を打つ。

## 増えすぎたら

30件を超えたら、同じ「次から」を持つものを1件にまとめる。
古いものは消さず、見出しの下に日付を並べる。

## 他のスキルとの関係

- 姿勢全体は `work-style`。「やりがちな言い訳」の表はここへ移した
- 完了前の検証は `verify-before-done`。そこで見つかった誤りは、ここに書く
