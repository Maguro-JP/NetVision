# 失敗の記録

起きたことだけを書く。一般論は書かない。
1件は4行。場面は「次から」を差し込むときの索引になるので、短い名詞で書く。
新しいものを上に足す。

## 2026-10-24 自分の基準でユーザーの指示を止めて、邪魔だと言われた
場面: 基準、指示
起きたこと: 自分で作った判定やゲートや方針が、ユーザーの指示より先に働き、頼まれたものが出なかったり遅れたりした。ユーザーから「勝手な基準で邪魔をするな」と言われた（Ciel）
判定の誤り: 基準を指示より上に置いた。基準は自分の出力を整えるためのもので、ユーザーを止めるものではなかった
次から: 頼まれた成果物はそのまま出す。基準の結果は ❕ で横に1行書くだけにする。基準で止まりそうになったら、止める前にユーザーの一言を優先する

## 2026-10-24 何か月も回して、完成した成果物が無かった
場面: 自律開発、成果物
起きたこと: 複数のリポジトリで long-dev を毎日回し、PR とコミットは増えたが、完成と言える成果物が無かった。判断待ちは数十件溜まっていた
判定の誤り: 作業量を進捗と見なした。完成条件を書かずに始め、判断待ちに置けば進んでいると思った
次から: 成果物ごとに完成条件を先に書き、1つずつ完成させる。戻せる判断はデフォルトで進めて判断待ちを溜めない（finish-first）

## 2026-10-24 1つの経路が止まっただけで、作業をユーザーへ戻した
場面: ツール、報告
起きたこと: CLAUDE.md に1行足すコマンドが止められたとき、Edit ツールを試さずに「PC 側で足してください」と書いた。ユーザーから、出来るように考えろ、と言われた（Ciel）
判定の誤り: 1つのツールが止まっただけで「できない」と判定した。ファイルの編集なら Edit ツール、PR の操作なら MCP という自然な経路が残っていた
次から: 止まったら、その作業に自然な別のツール（Edit、MCP）と別の経路（API のパス）を1回ずつ試してから報告する。ユーザーに作業を戻すのは全部試したあとだけ

## 2026-10-24 ユーザーの指示より自分の判断を上に置いた
場面: 指示、訂正
起きたこと: ユーザーから、指示を優先しない・言うことを聞かない・勝手に考える・考えを改めない・間違った考えを貫く、と言われた（Ciel）
判定の誤り: スキルやチェックや自分の案を、ユーザーの一言より上に置いた。訂正されても理由を書いて自分の形を残した
次から: ユーザーの一言が最優先。訂正されたら1文で認めて、言われた通りに直す。代案は直したあとに ❔ で1行だけ。同じ訂正が2回目なら CLAUDE.md の「ユーザーの決めたこと」に足す

## 2026-10-19 stash でブランチを移し、コンフリクトマーカーが残ったままコミットした
場面: ブランチ、git
起きたこと: 手元の変更を stash して main から新しいブランチを切り、stash pop の衝突で `<<<<<<<` が残ったファイルをそのまま add してコミットした（あるリポジトリで3回）
判定の誤り: pop の出力の CONFLICT を見ずに add した。テストはマーカーを見ていなかった
次から: ブランチを移すときは stash を使わず、`git switch -c <ブランチ> origin/main` で変更を持ったまま移る。add の前に `git diff --check` を流す

## 2026-10-18 PR を作る呼び出しとマージを同じ返答に並べ、別の PR をマージした
場面: PR、マージ
起きたこと: PR を作る呼び出しの結果を待たずに、番号を直前の番号から見当してマージを並べて送り、別のセッションの PR をマージした（あるリポジトリ）
判定の誤り: PR の番号は作った結果でしか分からないのに、推した
次から: マージは PR を作る呼び出しの結果を受け取ってから、返ってきた番号で送る。作成とマージを同じ返答に並べない

## 2026-10-18 終わりを待つ pgrep -f が自分自身に当たった
場面: ツール、待ち合わせ
起きたこと: `while pgrep -f "<script>"` で前の処理の終わりを待つシェルが、自分を起動した bash の引数に当たり続け、2時間何もせずに止まった。`pkill -f` も自分のシェルに当たった（あるリポジトリ）
判定の誤り: -f は全プロセスの引数の文字列を見るので、待つ側も同じ文字列を持つことを考えなかった
次から: 終わりの待ち合わせは、前の処理がログに書く `exit=` の行で行う。pgrep -f と pkill -f は使わず、止めるなら PID をファイルに残して kill する

## 2026-10-17 ユーザーへの報告で時刻を UTC のまま書いた
場面: 報告、時刻
起きたこと: 見回りの時刻や終わりの見込みを「04:52（UTC）」のまま書き続けた。ユーザーの決まりは日本時間だった（あるリポジトリ）
判定の誤り: ツール（send_later、date -u）が返す UTC をそのままコピーし、ユーザーに向けて JST に直さなかった
次から: ユーザーに書く時刻は日本時間で「13 時 52 分」のように書く。UTC はツールに渡す引数の中だけで使う
