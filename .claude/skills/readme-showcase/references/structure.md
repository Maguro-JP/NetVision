# README の節ごとの中身と例

節の順は SKILL.md の表。ここは、各節に何を書き、どのくらいの長さにするかと、日本語の例。
長さの目安は、README 全体で 100〜250 行。100 行を超えたら目次を置く。長い物は docs に出して README から辿る。

## タイトル

リポジトリの名前と同じにする。パッケージの名前が違うなら、括弧で添える。ロゴがあれば中央に置き、タイトルの上に出す。

```markdown
# Ciel
```

## 1 文

何を・誰のために・どうする物かを 1 文、120 文字以内で、タイトルの直下に自分の行で書く。
GitHub のリポジトリの説明と同じ文にする。引用（`> `）にしない。

```markdown
Claude Code の作業の決まりとフックを、複数のリポジトリに同じ形で配るためのスキル集です。
```

## バッジ

改行で区切って並べ、節の見出しは付けない。置けるのは根拠のある物だけ（`badges.md`）。
CI の状態、ライセンス、最新の版、対応 OS の 4 種類で足りる。数で飾らない。

```markdown
![CI](https://img.shields.io/github/actions/workflow/status/<owner>/<repo>/ci.yml?branch=main)
![License](https://img.shields.io/github/license/<owner>/<repo>)
```

## スクリーンショット

アプリなら起動したスクリーンショット（PNG）か操作の GIF を、1 文の下に置く。ライブラリなら使う所のコードか図。
スクリーンショットは `docs/images/` に置き、相対パスで参照する。外部の画像ホストに置かない（消えると壊れる）。
スクリーンショットに個人の名前、メール、鍵、内部の場所が写っていないかを content-audit で見る。

例: `![画面](docs/images/screenshot.png)`

## 特長

3〜6 個。機能の名前ではなく、使う人に何が起きるかを書く。

```markdown
## 特長

- フックが PR の前に検査を通し、通らなければ止めます
- スキルを 1 本のコマンドで全リポジトリに配ります
- 日本語の文を機械で校正します
```

## クイックスタート

5 手以内。前提 → 入れる → 動かす → 見える物、の順。番号付きで、コマンドは code block。
初めての人が、隠れた前提なしに動かせること。鍵が要るなら、どこで取るかを書く。

```markdown
## クイックスタート

前提: Python 3.11 以上。

1. 取る
   ```bash
   git clone https://github.com/<owner>/<repo>.git && cd <repo>
   ```
2. 動かす
   ```bash
   python3 app.py
   ```
3. ウィンドウが開き、最初の画面に「新しく作る」が見えます
```

## インストール

前提（OS、版、鍵）と手順。クイックスタートで足りるなら省き、更新の仕方や別の入れ方（pip、Setup.exe）があるときに書く。
パッケージ置き場（PyPI、npm）に公開している根拠が無ければ、その入れ方を書かない。

```markdown
## インストール

Windows は Releases の `Setup.exe` を実行します。ほかの OS は上のクイックスタートの通りです。
```

## 使い方

よく使う操作を 2〜3 個、code block で。CLI があれば CLI の例、import できるなら import の例。
出力の例があると、動いたかどうかを読む人が自分で確かめられる。

```markdown
## 使い方

```bash
python3 scripts/check.py docs/
```

出力の最後の行が `誤り 0` なら通っています。
```

## 設定

環境変数と設定ファイルを表にする。名前、既定、何に効くか。根拠はコードと `.env.example`。

```markdown
## 設定

| 変数 | 既定 | 何に効くか |
|---|---|---|
| `APP_PORT` | 8080 | 待ち受けのポート |
```

## 困ったとき

よくある失敗と直し方を 2〜5 個。問い合わせ先（Issue）を 1 行。

## 開発

テストの流し方、貢献の受け方（PR を受けるか、決まりの場所）。CONTRIBUTING.md があれば、そこへのリンクだけ。

## ライセンス

ライセンスの名前と LICENSE へのリンク。必ず最後の節。ライセンスが無いなら、先に決める（無いまま公開しない）。

```markdown
## ライセンス

MIT License。[LICENSE](LICENSE) を見てください。
```

## 魅せる README の 10 の問い

`scripts/readme_check.py` が同じ 10 項目を機械で見る。人が見るときの問い。

1. タイトルを見て、何の物か分かるか
2. 1 文を読んで、自分に要るか判断できるか（120 文字以内）
3. バッジは根拠のある物だけで、壊れていないか
4. スクリーンショットか図があり、動いている様子が見えるか
5. クイックスタートを上から打てば、5 手以内で動くか
6. インストールに前提と手順があり、コマンドが code block か
7. 使い方に、よく使う操作の例が code block であるか
8. ライセンスが最後にあり、LICENSE のファイルがあるか
9. リンクが全部つながるか
10. 空の節、置き場所の語（TODO、`<名前>`）、英語と日本語の見出しの混在が無いか。100 行を超えたら目次があるか
