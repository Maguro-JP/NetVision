# 難易度とモデル

指示の難易度でモデルを選ぶ。`scripts/fanout.py` がこの表を読むので、モデルの ID はここだけに書く
（ID は変わる。スキルの文やフックに散らさない）。表の列の名前と順番は変えない。

## モデルの表

「親と同じ」は、親のセッションの `session_context.model` をそのまま渡す。Agent ツールでは model を省く（親のモデルで動く）。

| 難易度 | create_session の model | Agent の model |
|---|---|---|
| 難しい | 親と同じ | 親と同じ |
| 普通 | claude-sonnet-5-5 | sonnet |
| 易しい | claude-haiku-5-5 | haiku |

## 難易度の語

題と説明にこの語があれば、その難易度にする。複数に当たれば、難しい側にする。
どれにも当たらず、規模の決まりにも当たらなければ、普通にする。

| 難易度 | 語 |
|---|---|
| 難しい | 設計、原因の分からない、原因不明、不具合の原因、フックの判定、ゲートの判定、判定を直す、複数のスキル、またがる、移行、アーキテクチャ、競合、セキュリティ |
| 普通 | 実装、テストの追加、テストを足す、書き直し、書き直す、直す、追加、足す、作る |
| 易しい | 一覧の更新、一覧を直す、置換、配布、配る、確認、要約、検索、誤字、リンクを直す、名前の変更、数える |

## 規模の決まり

語より先に見る。値は私の推測で、ここを書き換えれば変わる。

| 決まり | 値 |
|---|---|
| 手数がこの数以上なら難しい | 40 |
| 触るスキルがこの数以上なら難しい | 3 |
| 手数が分からないときの見積もり（難しい） | 30 |
| 手数が分からないときの見積もり（普通） | 15 |
| 手数が分からないときの見積もり（易しい） | 5 |

## 親のモデルと Agent の model

親のモデルの ID の先頭で、Agent ツールに渡す名前を決める（難しい作業を Agent に出すときに、名前で書きたい場合）。

| ID の先頭 | Agent の model |
|---|---|
| claude-fable | fable |
| claude-opus | opus |
| claude-sonnet | sonnet |
| claude-haiku | haiku |

## 根拠

- 普通の難易度の作業（README の書き直し、フックの直し）は、普通のモデルで 2〜3 分で終わった
- 取りまとめる側に上のモデルを、分けた側に下のモデルを置く形は、公開されている進め方と同じ（`docs/knowledge/tech/` の並列の進め方の知識）
- 易しいモデルは、長いプロンプトで確認を飛ばしやすいという報告がある。易しいのは、検査のある作業（一覧、置換、配布）だけにする
