# 用語の対応表

技術用語は、開発者の間で通る語をそのまま使う。自分で訳語を作らない。
訳語を作ると、書いた本人にしか通じなくなる。「枝」「門」「容器」「走査」は、読む人には別の物に見える。 <!-- ja-proofread: ignore -->

判断の基準は3つ。

1. 公式の日本語ドキュメント（GitHub Docs、Microsoft のスタイルガイド）で使われている語があれば、それ
2. なければ、日本の開発者が会話で使う語（カタカナか英語のまま）
3. 日本語の一般語で十分に伝わるものは日本語（直す、確かめる、記録、ローカル、手元）

## 使う語と、使わない訳語

| 使う語 | 使わない訳語 | 英語 |
|---|---|---|
| ブランチ、作業ブランチ、main ブランチ | 枝、作業枝、本線 | branch, main |
| デフォルトブランチ、デフォルト | 既定ブランチ、既定 | default |
| トピック | 題目 | topic |
| タイトル | 題、題名 | title |
| ゲート | 門 | gate |
| マーク、マーカー | 印、目印 | mark, marker |
| コンテナ | 容器 | container |
| プロキシ | 中継 | proxy |
| スキャン | 走査 | scan |
| コードブロック | 囲み | code block |
| インデント | 字下げ | indent |
| テスト、自己テスト | 試験、自己試験 | test |
| チェック | 検品 | check, QA |
| コピー | 写し | copy |
| アーカイブ済み | 凍結済み | archived |
| レート制限 | 利用枠、枠切れ | rate limit |
| 紐づける、紐づけ先 | 結びつける、結びつけ先 | bind, bound session |
| 実行、次の実行 | 起床、次の起床 | run, next run |
| 実行される、起動する | 起きる、起こす（Routine やセッション） | fire, wake |
| デプロイ | 配備 | deploy |
| ユーザー | 利用者 | user |
| 親セッション | 束ねる側 | parent / orchestrator |
| ツール | 道具 | tool |
| 日本語 | 和文 | Japanese text |
| 文字 | 字 | character |
| サイクル、N周目 | 周、周N | iteration, cycle |
| N回目 | 回N | round N |
| 参考画像、リファレンス | 手本 | reference |
| ルール | 網 | rules |

そのまま使ってよい日本語: 手元、ローカル、直す、確かめる、記録、判断待ち、配布、片付け、見回り、
差し込む、返答、連絡、立てる（セッションを立てる）、伏せる（伏せ字）、既読、見張り。

## 書き方

- 固有名詞とコマンド、設定のキー、ツール名は原文のまま（PR、Issue、`gh api`）。ただし、ユーザーが別の語を使っていれば、その語が先（Routine はユーザーの語ではルーティン。`.claude/skills/user-terms/references/user-terms.md`）
- カタカナ語の長音は付ける（サーバー、ユーザー）。`rules.md` の表記の既定と同じ <!-- ja-proofread: ignore -->
- 1行の報告でも、助詞のある文にする。「枝移動完了」のような電報の形や、矢印だけでつないだ羅列にしない <!-- ja-proofread: ignore -->
- 新しい語を使いたくなったら、この表に足してから使う。表にない訳語は `proofread.py` が「勝手な訳語」として拾う
