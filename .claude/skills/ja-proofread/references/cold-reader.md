# 文脈を持たない読み手（cold reader）

出典: MaryCache/ja-cold-reader の `skills/cold-reader`（MIT License, Copyright (c) 2026 MaryCache）。
読み手への指示文と6つの型をそのまま使い、Ciel の手順に合わせて前後を書いた。

書き手は文脈を持っているので、文脈が無いと読めない箇所が自分では見えない。
README、説明文、質問への返事を出す前に、文脈を渡さないサブエージェント（Agent ツール、新しい文脈）に
本文だけを読ませ、次の6つの型を拾う。文体・翻訳調・比喩は別の層（proofread.py、textlint）で見るので、ここでは扱わない。

| 型 | 名前 | 例 |
|---|---|---|
| 1 | 指すものが決まらない | 「同じフォルダ」「残りの3つ」が何を指すか決まらない |
| 2 | 呼び名の言い直し・その場の造語 | すでにある呼び名を別の抽象的な言い方で言い直す |
| 3 | 借りた言葉を定義せずに使う | 相手の言葉をそのまま使い、本文の中で何を指すか書かない |
| 4 | 誰も言っていないことの否定 | 「Aではなく」の A を誰も主張していない |
| 5 | 前の段落の言い直し | 最後の段落が要約し直しているだけ |
| 6 | 主張の範囲がずれる | 自分の環境の話が一般論に読める |

## 手順

1. 読み手を1行で決める。誰が読み、何をすでに知っていて、何を知らないか
2. 自分で6つの問いを当てて直す（下の自己点検）
3. サブエージェントを1体起動し、下の指示文に読み手の1行と本文だけを埋めて渡す。会話の経緯、元のファイル、意図、前の版、直した箇所は渡さない
4. 指摘を1件ずつ、直すか、直さない理由（読み手の知識の出どころを名指し）を書く
5. 直した箇所が4件以上なら、直した版でもう一度だけ3を回す（新しい読み手で）。3回目は回さない

## 自己点検の問い

- 型1: 主語・目的語・「この」「同じ」「残りの」は、読み手にとって一つに決まるか。前の文から推測できる、は不可
- 型2: 抽象的な呼び名を別の抽象的な言い方で言い直していないか。本文で定義していない言い方を作っていないか
- 型3: 相手の言葉を使うとき、それが本文で何を指すかを書いたか
- 型4: 「Aではなく」の A を、誰が主張したか名指しできるか。できなければ否定を消す
- 型5: 最後の段落で、前の段落に無かったことを1つ挙げられるか。挙げられなければ削る
- 型6: その主張は、誰の・どこでの話か書いてあるか

## 読み手への指示文（そのまま渡す）


あなたは次の文章を、初めて読む読み手として読みます。書き手の事情は何も知りません。
このメッセージに書かれていないことは知らないものとして扱ってください。ファイルを開いたり、調べたりしないでください。

## あなたが演じる読み手

{{READER}}

この読み手が知っていることだけを前提に読みます。読み手が知らない言葉・事情は、本文に説明が無ければ「分からない」と判断します。

## 探すもの（この6つの型だけ）

1. **指すものが決まらない** — 主語・目的語・「この」「同じ」「残りの」などが、何を指すかこの読み手には一つに決まらない。前の文から推測すれば分かる、というのは「決まる」に含めない。
2. **呼び名の言い直し・その場の造語** — すでにある呼び名（例: 保管庫）を別の抽象的な言い方（例: サーバーの外に置いた控え）で言い直していて、新しく分かることが無い。または、本文で定義していない言い方をその場で作って使っている（例: サーバーの外）。
3. **借りた言葉を定義せずに使う** — 質問・題・他人の発言から借りた言葉（引用符つきの言葉や、相手の言い回し）を、その言葉が本文の中で何を指すか書かずに使っている（例: 「詰む」— 何が起きると詰むのかが無い）。
4. **誰も言っていないことの否定** — 「Aではなく」「Aより」の A を、本文中でも読み手の質問でも誰も主張していない。否定を外しても主張が変わらない。
5. **前の段落の言い直し** — 段落（特に最後の段落）が、前の段落で言ったことを要約し直しているだけで、新しく分かることが無い、またはほとんど無い。新しい点が1つだけあるなら、その1点を引用する。
6. **主張の範囲がずれる** — 誰の・どこでの話かが書かれておらず、書き手の環境の話が一般論（例: 「restic で送っておけば困らない」）や全員の話に読める。または逆に、一般論として言うべきことが個人の話に狭まっている。

## 探さないもの

上の6つの型に当たらない指摘はしないでください。文体の好み、語尾の単調さ、言い回しの自然さ、翻訳調、比喩、太字や箇条書きの量、誤字は対象外です（別の工程で見ます）。
指摘が無い文は書かなくて構いません。見つからなければ「指摘なし」とだけ書いてください。数を揃えるために弱い指摘を足さないでください。

## 出力形式（これ以外を書かない）

Markdown の表1つ。1行に1指摘。

| 段落# | 引用 | 型 | なぜこの読み手が困るか | 直し案 |
|---|---|---|---|---|

- 段落#: 空行で区切られたまとまりを上から 1, 2, 3 … と数える（箇条書きのまとまりも1段落）。
- 引用: 本文から問題の箇所をそのまま抜き出す（30字以内）。言い換えない。
- 型: 1〜6 の数字1つ。
- なぜこの読み手が困るか: この読み手が何を知らないから、何が分からないかを1文で。「分かりにくい」だけで終えない。
- 直し案: 具体的な書き換え、または「削除」。本文に無い事実が必要なら「（書き手が補う: 〜）」と書き、事実を作らない。
