## 既存のリポジトリ

手元に clone があるなら `sync.py --apply` を叩くだけ。無いなら clone してから。

スマホや Web のセッションで使うには**コミットが要る**。リモートのセッションは
リポジトリを clone し直すので、手元だけの変更は見えない。

## 新しいリポジトリ

新しく作ったリポジトリには、当然まだ何も入っていない。3通りある。

| 方法 | 手間 | 鍵 | 新規を自動で拾えるか |
|---|---|---|---|
| 作ったときに1回叩く | 毎回1コマンド | 不要 | いいえ |
| テンプレートリポジトリから作る | 最初に1回だけ | 不要 | はい（そこから作れば） |
| Raphael から配る | 最初に1回だけ | PAT を private に置く | はい |

**Raphael を勧める。** 何もしなくても新規リポジトリに入る。

## テンプレートリポジトリ

1. `.claude/skills/` と `.claude/policy/` を入れたリポジトリを作る
2. GitHub の設定で Template repository を有効にする
3. 以後、新規はそのテンプレートから作る

中身は最小でよい。

```
.claude/skills/          Ciel から入れたもの
.gitignore
README.md
```

`.claude/policy/<利用者名>.json` は入れない。リポジトリごとに
`workspace-policy` が規約を読んでから決めるもので、テンプレートで固定すると
規約を読まずに方針が決まってしまう。

テンプレートは Ciel を更新しても古くなる。`sync.py` の対象に入れておく。

## Raphael から配る

配布用の private リポジトリ（Raphael）に workflow を1本だけ置き、
そこから全リポジトリへ配る。毎週土曜 09:00（日本時間）。

以前は各リポジトリに1本ずつ workflow を置いていた。同じことをする
ジョブがリポジトリの数だけ動くので、増えるほど無駄になる。集約すると
週あたりのジョブがリポジトリ数から1に減る。

やること。

1. リポジトリ一覧を取る
2. 凍結済み・fork・書き込み権限の無いもの・除外リストにあるものを外す
3. 最終コミットが180日より古いものを外す
4. コミットが1つも無いリポジトリを外す（既定ブランチが実在せず PR を作れない）
5. 残ったものについて、`.claude/skills/` の有無と差分を見る
6. 差分があるものにだけ `ciel-sync` ブランチで PR を出す
7. 本人しか見ていないリポジトリなら、そのままマージまで進める
8. 差分が無ければ何も報告しない

7 の判定は star 1以下・fork なし・Pages なし・Discussions なし。
どれかに当てはまれば他の人が見ている場所とみなして PR のまま残す。
同期 PR の中身は Ciel の複製で、直すなら Ciel 側で直すため、
一つずつ人が確認する意味は薄い。ただし他人が見ている所では止める。

ブランチと PR は使い回すので、開いている同期 PR は常に最大1本になる。

配布元は Ciel を認証なしで clone する。Ciel は public のままでよく、
鍵は private の Raphael にだけ置く。

## やらない方がよいこと

**public なリポジトリに、全リポジトリへ書き込める PAT を置くこと。**
Ciel から各リポジトリへ push する形にすると、これが必要になる。
secret 自体は公開されないが、鍵が漏れたときの被害範囲が最大になる。
だから配布元を private の Raphael に分けている。

**PAT を clone の URL に埋めること。** clone が失敗するとトークンが
エラー文に載ってログへ出る。`gh auth setup-git` に任せる。

**凍結済みのリポジトリに何かを言うこと。** 対象から外すだけでよい。
意図して凍結したものについて、毎回「対象外です」と報告されるのは邪魔になる。
