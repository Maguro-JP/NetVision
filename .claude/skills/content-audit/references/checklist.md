## リポジトリで見えるもの

private なら共同作業者と、権限を持つ連携アプリに。public なら誰にでも。

| どこ | 何が見える | 気づきにくい点 |
|---|---|---|
| ファイル | 今の中身 | 追跡していないファイルは次の `git add` で入る |
| 履歴の追加行 | 一度でもコミットした行 | 消した行も `git log -p` で読める |
| 消したファイル | 一度でも追加したファイル | `.env` を消しても履歴に残る |
| コミットメッセージ | 本文と末尾の署名行 | 自動で付く行（セッションの URL など）が全コミットに入る |
| 著者 | 名前、メールアドレス、コミットの時刻と時差 | 時差で生活圏が分かる。メールは `git log` で誰でも取れる |
| Issue と PR | 題、本文、コメント、レビューコメント | 閉じたものも残る。本文に貼った URL や ID |
| リリース | 題と本文、添付ファイル | 添付の中身はスキャンしない |
| リポジトリの設定 | 説明、ホームページ、topic | 説明に内部の名前を書きがち |
| Wiki | ページの中身 | API で読めないので手で見る |
| Pages | 公開サイト | ビルドの出力に環境の値が混ざることがある |
| Actions のログ | 各ステップの出力 | secrets はマスクされるが、`env` や設定の echo は見える。90日残る |
| fork | 上と同じ履歴のコピー | 元を直しても fork は直らない |

## 人にしか判断できないもの

スキャンでは拾えない。公開前と、月に1度、目で見る。

- 人名、顧客名、取引先名。ハンドルと本名が結びつくもの
- 社内の決定、未公開の計画、まだ出していない製品の名前
- 画像、動画、PDF に写ったもの（名前、画面の URL バー、通知、タブのタイトル、机の上）
- 「非公開リポジトリの名前」の一覧にない名前。一覧は人が育てる
- 文脈で分かる所在地（駅名、天気、祝日、時差）
- 他人の著作物のコピー（ライセンス不明の文章やコード）
- テストデータに紛れた本物（本物のメール、本物の注文番号）

## 読む人が不快になるもの

語の一致ではなく、読む人の立場で読む。スキャンは候補を出すだけ。

| 形 | 例の形 | 直し方 |
|---|---|---|
| 人の発言の引用 | 「〜しろ」と言われた、「〜じゃないか」と怒られた | 言われたことではなく、決めたこと・変えたことを書く。`lessons` の4行の形 |
| 感情・叱責の描写 | ユーザーが怒った、呆れられた、キレられた | 書かない。何が起きて何を直したかだけ |
| 責任を人に向ける | ユーザーが言わなかったので、指示が曖昧だったため | 自分の判定の誤りとして書く。「確かめなかった」 |
| 罵倒・侮蔑 | 人や成果物への強い語 | 消す。評価は数字と事実で |
| 見下し・皮肉 | 初歩的なミス、素人考え、当然ながら | 消す。読む人が知らないことを前提にしない |
| 他人の評価 | 〜さんのコードは雑、前任者が放置した | 人ではなく状態を書く。「テストがなかった」 |
| 自分への過剰な卑下・謝罪 | 申し訳ありません、私の能力不足で | 1文で認めて直す。長い謝罪は読む人の時間を奪う |
| 性的・暴力的・差別的な内容 | 作業と無関係な比喩、属性で人をくくる語 | 消す |

AI が書く記録で特に出やすいのは、上の3つ（引用、感情、責任）。ユーザーの言葉を写すと、
その場の勢いまで残り、あとから読む人（ユーザー自身を含む）が不快になる。

## 伏せ方

| 見つかったもの | 伏せ方 |
|---|---|
| 非公開リポジトリの名前 | `<owner>/<repo>`、「あるリポジトリ」。何を作っているかの説明も薄める |
| メールアドレス（文書内） | 消す。連絡先が要るなら GitHub のプロフィールへ誘導 |
| メールアドレス（著者） | 以後は `<id>+<login>@users.noreply.github.com` を `git config user.email` に。過去の分は「履歴を書き換えるか」 |
| セッション・Routine の ID、セッションの URL | 消す。記録に残すなら ID ではなく日付とタイトルで指す |
| 費用の数字 | 消す。要るなら非公開の場所（個人の記録、非公開リポジトリ）へ |
| 内部ホスト名、私有アドレス | `example.internal`、RFC 5737 の例示用（`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`）に置き換える |
| ユーザー名入りのパス | `~/`、`<home>/`、`/path/to/` に |
| 電話番号、住所 | 消す |
| 非公開サービスへのリンク | 消すか、公開の場所に写してそちらを指す。リンク先が開けなくても、存在と名前は漏れる |
| 画像 | 撮り直すか、該当部分を塗る。メタデータ（EXIF の位置情報）も消す |
| 認証情報のファイル、`.env` | 中の値をローテートしてから消す（`secret-leak-check`）。消すだけでは漏れたまま |
| 不快な表現 | 上の表。人の言葉を「決めたこと」に書き換える |

伏せたあとは `scripts/audit.py --diff` で、伏せ漏れがないことを見る。

## GitHub 側の設定

ユーザーが GitHub の画面で行う。AI からは変えられない。

| 設定 | 場所 | 効き |
|---|---|---|
| メールアドレスを隠す | Settings → Emails → Keep my email addresses private | 以後の Web 上の操作が noreply になる |
| メールが出る push を止める | 同 → Block command line pushes that expose my email | 個人のメールで作ったコミットの push が拒まれる |
| Wiki を切る | リポジトリの Settings → Features → Wikis | 使っていないなら切る |
| Actions のログの保存期間 | Settings → Actions → General → Artifact and log retention | デフォルト 90 日。短くできる |
| 公開範囲 | Settings → General → Danger Zone → Change visibility | private に戻しても、fork とキャッシュは戻らない |

## 履歴を書き換えるか

書き換えるかはユーザーが決める。AI は材料を出すだけ。

- 書き換えても、fork、clone、GitHub のキャッシュ、イベント API には残る。「見えにくくする」だけ
- 書き換えると全コミットの SHA が変わる。開いている PR、clone している人、固定リンクが全部ずれる
- 著者のメールだけなら、`git filter-repo --mailmap` で名前とメールを置き換えられる。force push が要る
- 書き換えた日は記録に残す。あとで SHA を見て混乱しないため

書き換えないと決めたときは、以後の分だけ止める（上の「GitHub 側の設定」と `git config user.email`）。
