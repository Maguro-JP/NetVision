# 中身の精査

書いたものは人が読む。private でも共同作業者、レビュー担当、画面を共有した相手、
将来 public にしたときの誰か、そして読み返す自分。見えるのはファイルの今の中身だけではなく、
履歴の追加行、消したファイル、コミットメッセージ、著者のメールと時差、Issue と PR の本文と
コメント、リリース、説明文、Wiki、Actions のログまで。

止めるものは2種類。

| 種類 | 何 | なぜ止める |
|---|---|---|
| 機密・個人を指すもの | 非公開リポジトリの名前、メール、セッションと Routine の ID、費用、内部の場所、認証情報のファイル、個人の端末のパス、画像に写ったもの | 読む人に知らせる必要がなく、知られると困る |
| 読む人が不快になるもの | 罵倒・侮蔑、人の発言の引用、怒りや叱責の描写、責任を人に向ける書き方、見下し・皮肉 | 読む人の時間を奪い、書いた側の信用を削る。記録には何を決めたかだけが要る |

答える問いも2つ。

| 問い | 見るところ | 見つかったときの意味 |
|---|---|---|
| これから出すものに、見せてはいけないものがないか | 作業ツリー、差分 | まだ止められる。伏せれば済む |
| すでに出ているものに、何があるか | 履歴、GitHub 側 | もう見えている。伏せても clone や fork に残る。消すかはユーザーが決める |

## 鍵のスキャンとの違い

| | secret-leak-check | content-audit |
|---|---|---|
| 見るもの | API キー、トークン、秘密鍵、認証情報付きの URL | 名前、連絡先、ID、費用、内部の場所、リンク、画像、著者、GitHub 側、不快な表現 |
| 見つかったら | 先にローテート | 伏せる、書き直す。すでに見えるものはユーザーが決める |
| 判定 | 形で機械が決められる | 見せてよいかは人が決める。スキャンは候補を出す |

PR の前は両方を回す。言い回しそのもの（誤字、翻訳調、表記）は `ja-proofread`。

## 手順

### 1. 範囲を決める

| 状況 | 範囲 |
|---|---|
| コミット前、PR の前 | `--diff`（未コミット）か `--diff origin/main..HEAD` |
| 記録を書いたあと（lessons、日報、知識） | `--diff`。人の言葉の引用と感情の描写が混ざりやすい |
| private を public にする前 | `--all <owner/repo>`。履歴と GitHub 側を省くと公開の意味がない |
| すでに public で、月1の見直し | `--all <owner/repo>` |
| 「書いてしまった」 | `--history` で、押し出された範囲を見る。push 済みなら「すでに見える」 |

### 2. スキャンする

```bash
.claude/skills/content-audit/scripts/audit.py --diff                   # 未コミットの変更
.claude/skills/content-audit/scripts/audit.py --diff origin/main..HEAD # PR の差分
.claude/skills/content-audit/scripts/audit.py --tree                   # 作業ツリー（追跡していないファイルも）
.claude/skills/content-audit/scripts/audit.py --history                # 全コミット。追加行、メッセージ、著者、消したファイル
.claude/skills/content-audit/scripts/audit.py --github <owner/repo>    # 説明、Issue と PR の本文とコメント、リリース、設定
.claude/skills/content-audit/scripts/audit.py --all <owner/repo>       # 上の全部
```

拾うもの。

- 機密・個人を指すもの: メールアドレス、セッションと Routine の ID とセッションの URL、ユーザー名入りのパス、郵便番号、電話番号
- 内部の場所: 私有アドレス、内部ホスト名、グローバルアドレス
- 非公開サービスへのリンク: Google ドキュメント、Notion、Slack、Figma、Atlassian
- 費用の数字
- ファイル名: 認証情報のファイルと `.env`、データのファイル（sql、csv、har、log）、画像と動画と PDF の一覧
- 非公開リポジトリの名前（一覧があるとき）
- 不快な表現: 罵倒・侮蔑の語、8 文字以上の発言の引用、怒りと叱責の描写、責任を人に向ける書き方、見下しの語
- 履歴では、著者ごとのメールと時差、一度でも追加した認証情報のファイル名

鍵やトークンは `secret-leak-check` の `scan.py` が見る。重ねて見ない。

検出（重大・注意）があれば終了コード 1。同じ値は1件にまとめて場所を並べる。1つの URL が
全コミットに入っていても、決めるのは1件。

### 3. 判定する

検出は漏れではない。1件ずつ見て、見せてよいものかを決める。

- 見せてよいか決めるのはユーザー。スキャンが拾ったものを「問題ない」と AI が決めない。判断がつかないものは伏せる側に倒し、`❔` で1行聞く
- 例示（`example.com`、RFC 5737 のアドレス、`<owner>/<repo>`）、返信不可のアドレス、コンテナのデフォルトの名前（`/home/user/`）、8文字未満の短い引用（「まとめて」のような指示の語）はデフォルトで拾わない
- 不快な表現の候補は、読む人の立場で読み直す。語が一致しても、自分の失敗を書いた記録（「〜のせいだと疑った」）は残してよい。人に向いているものだけ直す
- 意図して置いた例は、行末に `content-audit: ignore` を書くか、`.contentallow` に1行足す（正規表現は値に、`path:<glob>` はファイルに当たる）。足す前に、それが本当に見せてよいものか見る

### 4. 報告する

値そのものは報告に書かない（スキャンの出力はデフォルトで伏せる。`--show` は手元の端末で自分だけが見るとき）。
値が同じものは1件に数え、「まだ止められる」と「すでに見える」を分けて数える。

```
重大 2 / 注意 1 / 情報 3
まだ止められる 1 / すでに見える 2
  人の発言の引用     LESSONS.md 1 箇所                          → 言われたことではなく、決めたことを書く
  セッションの URL   コミットメッセージ 96 箇所、PR 本文 N 件   → 以後は付けない。履歴はユーザーが決める
  著者のメール        85 コミット                              → 以後は noreply に。履歴はユーザーが決める
```

3行を超えるなら Markdown のファイルに書いて `★` で渡す。検出ゼロでも「安全」とは言わない。
「このルールでは検出されなかった」と言い、人が見るもの（`references/checklist.md`）を1行添える。

### 5. 伏せる・書き直す

伏せ方は `references/checklist.md` の表に従う。非公開リポジトリの名前は `<owner>/<repo>`、
メールは消すか noreply、ID は日付とタイトルで指す、費用の数字は非公開の場所へ、内部の場所は例示用の値へ。
不快な表現は、人の言葉を写さず「何を決めたか」「何を変えたか」に書き換える。
伏せたあと `--diff` をもう一度回し、伏せ漏れがないことを見てから PR にする。

すでに見えるものは、伏せても残る。履歴を書き換えるか、以後の分だけ止めるかはユーザーが決める。
材料（件数、書き換えると変わるもの、残るところ）を出して `❔` で聞く。聞かずに書き換えない。

## 非公開の名前の一覧

非公開リポジトリの名前は、形では拾えない。一覧を渡すと拾う。

- 置き場所は必ずリポジトリの外。`~/.config/content-audit/names.txt`、環境変数 `CONTENT_AUDIT_NAMES`、
  または `--names <file>`。リポジトリに入れると、一覧そのものが漏れる
- 1行1つ。`owner/repo` か名前だけ。4文字未満の名前は普通の語とぶつかるので、`owner/repo` の形で書く
- 手元の端末では GitHub CLI で作れる

```bash
mkdir -p ~/.config/content-audit
gh repo list <owner> --visibility private --limit 200 --json nameWithOwner -q '.[].nameWithOwner' > ~/.config/content-audit/names.txt
```

クラウドのセッションではこの一覧を作れない。プロキシがリポジトリ単位の API しか通さない
（2026-10-18 に確かめた。`user/repos` は `sessions are bound to their configured repositories`）。
一覧がないときはスキャンが「非公開の名前は検査していない」と出す。その1行を報告に残す。

## 人が決めること

- 何を見せてよいか（ハンドル、著者名、時差、費用の数字、private の中での内部の名前）
- 履歴を書き換えるか、以後の分だけ止めるか
- GitHub 側の設定（メールを隠す、Wiki を切る、ログの保存期間）。AI からは変えられない
- 名前の一覧に何を足すか

決まったことは、そのリポジトリの CLAUDE.md に「書かないもの」として1行で残す。
AI が自分で決めてよいのは、デフォルトの伏せ方で伏せることと、不快な表現を「決めたこと」の形に書き直すことだけ。

## 定期に回す

public なリポジトリは月に1度 `--all` を回す。`dev-report` の月報を書くときが区切り。
private でも、記録（lessons、docs/knowledge）が増えるリポジトリは同じ周期で `--history` を見る。
Ciel 自身は `skill-upkeep` の観察で見る。

## やらないこと

- 検出した値を会話や報告に丸写しすること。報告が新しい漏れの経路になる
- 検出ゼロで「安全」と言うこと
- private だからとスキャンを省くこと。private は「今は見る人が少ない」であって「見られない」ではない
- ユーザーに聞かずに履歴を書き換えること、リポジトリの設定を変えること
- 非公開の名前の一覧をリポジトリに入れること
- 誤検知を黙らせるために `.contentallow` を増やすこと。足す前に中身を見る
- スキャンが通ったことを理由に、画像と Wiki と Actions のログを見ないこと
- 不快な表現のスキャンを「言葉狩り」に使うこと。語ではなく、読む人がどう感じるかで決める
