# インテュイティブ、ユーザーフレンドリー、ストレスフリーな UI

ユーザーが決めたこと。UI の設計は、インテュイティブ、ユーザーフレンドリー、ストレスフリーを心がける。
使う人は説明書を読まない。画面を見てやりたいことがすぐ分かり、押せば答えが返り、間違えても戻せて、待たされず、邪魔されない。
それが完成の形で、機能が動くだけでは未完成。「慣れれば分かる」「設定で変えられる」を使いにくさの言い訳にしない。

## 1. インテュイティブ（見れば分かる）

- 最初の画面に、使う人がいちばんしたいことが見えている。隠したメニューの中に置かない
- 押せるものは押せる見た目、押せないものは押せない見た目。div や span をクリックの対象にしない
- ボタンの文言は、押すと何が起きるかを言う（「保存する」「書き出す」）。「OK」「送信」「実行」にしない。同じ操作には画面のどこでも同じ名前を使い、押したあとの表示も同じ語で返す
- 操作は、効く対象のそばに置く。並びは作業の順にする
- 言葉は使う人の言葉。内部の名前（テーブル名、設定のキー、エラーコード）を見せない
- 同じ種類のものは同じ場所、同じ形。OS や、みんなが知っているアプリの慣習に合わせる
- デフォルトが入っていて、何も決めなくても始められる

## 2. ユーザーフレンドリー（答えが返り、戻せて、困らない）

- 押したら 0.1 秒以内に反応が見える。1 秒を超えるなら進みを見せ、10 秒を超えるなら中止できる。画面を固めない（sleep や重い処理を画面のスレッドに置かない）
- 戻せる操作には「元に戻す」を付け、確認のダイアログを出さない。確認は戻せない操作だけにし、何が消えるかを書く。「本当によいですか」だけにしない
- エラーは、何が起きたか・何をすればよいかを、起きた場所のそばに書く。例外の原文やスタックトレースを見せない。入力した内容を消さない
- 何も無い画面（最初、検索 0 件）には、次に何をするかを書く
- キーボードだけで操作でき、フォーカスが見える。入力にはラベル、画像には alt。色だけで意味を伝えない。文字は 12px 以上、文字と背景のコントラストは 4.5:1 以上
- 助けは画面の中に置く（短い説明、置いたときの説明）。説明書に飛ばさない

## 3. ストレスフリー（手数が少なく、待たせず、邪魔しない）

- よく使う作業は、起動から 3 手以内。手数を数えて書く
- 確認・通知・ポップアップを増やさない。作業を遮るモーダルは、答えが要るときだけ。自動再生・音・勝手に動くものを出さない
- 前回の状態（ウィンドウの大きさ、最後に使ったもの、入力の途中）を覚え、次はそこから始まる
- 作業を失わせない。自動で保存し、落ちても復元する。再読み込みで入力を消さない
- 起動は速く、遅いなら進みを見せる。待っている間も、できることは触れる
- 選択肢は 7 つまでにまとめる。多いものは絞り込みや段階で出す
- ターミナルを見せない（desktop-app）

## 手順

1. 作る前に、使う人の主な作業を 3 つまで書き、それぞれの手順（起動から完了までの操作）を数える。finish-first の完成条件に「作業 X が N 手で終わる」を入れる
2. 作りながら、`references/checklist.md` の問いで見る。フック（`hooks/ui_nudge.py`）が書き込みのたびに、機械で拾える物を 1 行で知らせる
3. 完了と言う前に、主な作業ごとに「初めての人」として歩く。各操作で 4 つの問い（したいことに気づくか、操作が見えるか、操作と結果がつながるか、進んだと分かるか）に答え、1 つでも「いいえ」なら直す。スクリーンショットが撮れるなら撮って見る
4. `scripts/ui_check.py --diff <base>` を precheck が通し、注意として出す。注意は直す目安で、出す前に止める理由にはしない

## スクリプトとフック

| 何 | すること |
|---|---|
| `scripts/ui_check.py` | HTML・JSX・TSX・Vue・Svelte・JS・CSS と、tkinter・PySide・pywebview などを読み込む Python を見て、機械で拾える物（止まるダイアログ、ラベルの無い入力、文字の無いボタン、消したフォーカス、曖昧なエラー文、例外の原文、画面を固める sleep、押すと何が起きるかを言わないボタンの文言）を注意として出す。`--files` と `--diff <base>` |
| `hooks/ui_nudge.py` | PostToolUse（Edit、Write）。書き込んだファイルに同じ検査をかけ、1 行で知らせる。止めない。`UI_DESIGN_OFF=1` で止める |
| `scripts/test_ui_check.py` | 作った中身で、判定とフックを確かめる |
| `references/checklist.md` | 人が歩いて見る問い。取り込み元は docs/SOURCES.md |

## 他のスキルとの関係

- 起動の形（ウィンドウで開く、CLI を作らない）: `desktop-app`。このスキルは画面の中身
- 見た目の個性（色、書体、余白、動き）: Anthropic の frontend-design（取り込み元は docs/SOURCES.md）。このスキルは使いやすさで、見た目の好みは決めない
- 完成条件の書き方: `finish-first`。動かして確かめる: `verify-before-done`
