# 短い一言を全文のプロンプトにする

ユーザーは前の会話を前提に短く言う。「やれ」は直前の ❔ への答えで、「それも」は直前の成果物の隣にある。
一言だけを読んで聞き返したり、文字どおりに狭く作ったりすると、ユーザーは同じことをもう一度長く言うことになる。
対象と形は前の会話にある。そこから全文のプロンプトを組み立ててから動く。

## 決まりの出どころ

同じ目的の公開スキルを探した（2026-10-24）。見つかったのは、曖昧な指示から意図を推定して「確認してから実行する」もの
（claudskills.com の `intent-executor`。手順の本文は公開ページに無く、ライセンスの表記も無い）。
確認で止める段は、ユーザーの「聞き返すな」と合わないので取り込まない。意図を推定して動くという目的だけを共有する。
材料の順番と型は、このリポジトリの `follow-instructions`（優先順位）と `finish-first`（今の成果物）に合わせた。

## 1. いつ使うか

| 合図 | 例 |
|---|---|
| 短い（目安 40 文字以下） | 「やれ」「直して」「マージ」「続けて」 |
| 指示語がある | 「それも」「これで」「さっきの」「同じように」「全部」 |
| 動詞だけで対象が無い | 「入れて」「消して」「出して」「戻せ」 |
| 形が無い | 「報告して」（どの形かは、ユーザーの決めた形） |

対象と形がそろった依頼には使わない。そのまま `work-style` の着手前へ進む。
訂正の語（「違う」「勝手に」「言った通り」）があるときは `follow-instructions` の手順を先に行い、対象の読み方だけをこのスキルで補う。

## 2. 材料と順番

1. 今の一言（原文のまま）
2. このセッションでユーザーが言ったこと（`follow-instructions` の `directives.py` が毎ターン差し込む一覧。訂正が上）
3. 直前の自分の返答の ★ ↩ ❕ ❔（最後に出した成果物、落ちたもの、答え待ちの質問。このスキルのフックが短い一言のときに差し込む）
4. 今の成果物（`docs/reports/deliverables.md` の先頭の未完成。`finish-first` の `focus.py` が差し込む）
5. CLAUDE.md の「ユーザーの決めたこと」（出力の形、言語、マーク、GUI）
6. 直前のツールの結果と通知（落ちたテスト、CI、PR の状態）

上から順に見て、対象が決まったところで止める。下のものを上より優先させない。

## 3. 読み方

| 一言 | 読み方 |
|---|---|
| やれ、やって、はい、それで、進めて | 直前の ❔ への「はい」。❔ が無ければ、今の成果物の次の手順 |
| それ、これ、さっきの | 直前の ★ か ❔ の対象 |
| も、同じように、他も | 直前にした作業を、次の対象（一覧の次、残りのリポジトリ、同じ種類のファイル）に |
| 続けて、続き | 今の成果物の「残り」 |
| 直して、直せ | 直前の ❕ で落ちたもの。無ければ直前の ↩ の対象 |
| 全部、すべて | 直前に出した一覧の全件。一覧が無ければ、ユーザーの持つ全リポジトリ・セッション・PR |
| 戻して、戻せ | 直前の変更を元に。どこまでかは、直前の ★ の1つ前 |
| 報告して、見せて | ユーザーの決めた形（★ ↩ ❕ ❔ の行。3 行を超えればファイル） |
| 〜化しろ、スキルにしろ | そのリポジトリの作り方で。Ciel ならスキルの型に合わせ、公開されているものを先に探す |

どの材料にも当たらなければ、一言の語をそのまま対象にして、読める範囲で動く。

## 4. 組み立てる型

```
一言: <原文>
対象: <ファイル、PR、リポジトリ、スキル、セッション。具体名で>
やること: <動詞を手順に。1〜3 行>
形: <出力の形。ユーザーが決めた形>
完成条件: <動かして確かめられる文>
守る決まり: <当てはまる「ユーザーの決めたこと」>
補った根拠: <材料のどれから読んだか>
```

全文は頭の中でよい。会話に出すのは次の1行だけで、そのあとに成果物を出す。

`↩ 読み取り: 「<一言>」を、<材料>から「<対象>を<やること>。<形>」と読みました。`

ユーザーが「違う」と言えば、`follow-instructions` の訂正の手順に入る。
読み取りの行があるので、ユーザーは全文を言い直さずに、対象だけを直せる。

## 5. 聞き返さない

- 2つの読み方で成果物が変わるときだけ、文脈に近い方・取り返しのつく方で進め、↩ の行にどちらで読んだかを書く。❔ は直したあとに1行、1回（`follow-instructions` と同じ）
- 取り返しのつかない操作（削除、公開、課金、外部への送信）だけは、動く前に対象を ❔ で1行確かめる
- 「分からない」で止めない。読める部分を先に進める

## 6. フックが差し込むもの

`hooks/brief.py`（UserPromptSubmit）。一言が 40 文字以下か、指示語があって 120 文字以下のとき、
transcript から直前のユーザーの一言と自分の ★ ↩ ❕ ❔ を少しだけ、答え待ちの ❔ と一緒に差し込む。
通知とツールの結果は数えない。長い一言には何も出さない（毎ターンの差し込みを増やさない）。
短い一言の数は `~/.claude/state/prompt-from-context/metrics.jsonl` に残し、`skill-upkeep` が週報で「短い一言の数」と「聞き返した数」を比べる。
テストは `scripts/test_brief.py`。`PROMPT_FROM_CONTEXT_OFF=1` で止まる。

## 7. 他のスキルとの関係

- 指示の優先順位と訂正: `follow-instructions`
- 今の成果物と完成条件: `finish-first`
- 着手前に自分の言葉で返す: `work-style`
- 完了と言う前の検証: `verify-before-done`
