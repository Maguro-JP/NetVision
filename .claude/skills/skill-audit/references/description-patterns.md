# description パターン集

## 基本形

```
<動作・対象>を<するとき>。<具体的なトリガー語やユーザーの言い回し>。<除外条件>。
```

## 良い例

```yaml
description: Word文書(.docx)の作成・読み取り・編集を行うとき。「Wordファイル」「.docx」
  「報告書をWordで」といった言及、または見出し・目次・ページ番号付きの文書生成の依頼で使う。
  PDF、スプレッドシート、Googleドキュメントには使わない。
```

効いている要素：
1. 対象の拡張子を明示（`.docx`）
2. ユーザーが実際に打つ言葉（「報告書をWordで」）
3. 隣接する紛らわしい領域を明示的に除外（PDF、スプレッドシート）

## トリガー語の集め方

そのスキルを使わせたい場面で、ユーザーが打ちそうな文を5つ書き出す。
その中に出てくる名詞・動詞・ファイル拡張子を description に入れる。

例：スキル「デプロイのロールバック」
- 「本番を戻して」
- 「さっきのデプロイ、ロールバックして」
- 「リリース前の状態に戻したい」
- 「デプロイ失敗した、復旧して」
- 「v2.3.1 に戻す」

→ 「ロールバック」「デプロイ」「本番」「戻す」「復旧」「リリース」を入れる。

## 除外条件の書き方

隣接スキルとの境界線を1文で引く。

```
... ただし新規作成には使わず、既存ファイルの編集のみに使う。
```
```
... ローカル開発環境の再起動には使わない。
```

## アンチパターン

| 書き方 | なぜダメか |
|---|---|
| 「〜に便利なスキル」 | 発動条件がゼロ |
| 「高度な〜を実現します」 | 宣伝文であって判定材料でない |
| 「あらゆる〜に対応」 | 責務が広すぎて誤爆する |
| 20文字以下 | 判定材料が足りない |
| 本文と同じ内容の要約 | description は要約でなく発動条件 |

## 長さの目安

1〜3文、日本語で60〜200文字程度。長すぎても薄まる。
