## 探すファイル

決まった名前のもの。

```
AGENTS.md
CLAUDE.md
CONTRIBUTING.md
.github/CONTRIBUTING.md
docs/CONTRIBUTING.md
.github/CODEOWNERS
CODEOWNERS
docs/CODEOWNERS
```

glob で拾うもの。

```
.cursor/rules/*.mdc
.github/*.md
```

`.cursor/rules/` を入れているのは、Cursor と Claude Code の両方を使う人が
同じ規約を両方に置くため。片方にしか書かれていないことがある。

## 拾う記述

三種類に分けて探す。

### 人がマージする運用

```
人が…（見て|確認して|レビューして）…（Merge|マージ）
（人|人間|レビュアー|担当者）…（承認|approve）
（先に|必ず）… Merge してください
require(s) … (human|manual) … (review|approval)
do not (auto-merge|merge automatically)
自動…マージ…（しない|禁止|不可）
```

一つでも当たれば `auto_merge` を選ばせない。

### PR を1本ずつ

```
未マージ…（新しい|次の）PR…（作らない|出さない）
PR は…1本
積み上げ…PR…（禁止|しない）
one (open) (PR|pull request) at a time
```

当たれば `max_open_prs` を 1 にする。

### 枝の接頭辞

```
`<接頭辞>/` で始まる枝
から `<接頭辞>/<
```

## 取りこぼすもの

正規表現なので、書き方が違えば当たらない。

- 図や表だけで運用を示している場合
- 「レビューを経てから反映します」のような、動詞が一致しない言い回し
- 英語と日本語が混ざった文
- Wiki や issue にだけ書かれていて、リポジトリに無い規約
- 口頭やチャットでしか共有されていない取り決め

**検出が空でも「規約が無い」とは限らない。** 規約ファイルが存在するのに
何も当たらなかったときは、そのファイルを実際に読んでから決めること。
スクリプトの出力だけで判断しない。

## PR で走る CI

`.github/workflows/*.yml` のうち、`pull_request` で発火するものを列挙する。

ファイル名か `name:` に `policy` `規約` `ルール` が含まれるものは、
規約の検査とみなして印を付ける。これが落ちたときはコードの不具合ではなく
PR の出し方の問題なので、対応が違う。

判定は当てにならないこともある。印が付いていなくても、内容を見れば
規約の検査だと分かることがある。迷ったら中身を読む。

## 記録の失効の判定

`evidence.policy_digests` には、読んだ規約ファイルの内容の要約（sha256 の先頭16文字）を
ファイルごとに入れる。

```json
"policy_digests": {
  "AGENTS.md": "3f2a8c1d9e0b4756",
  ".cursor/rules/pr-workflow.mdc": "7b1e4a02cc8d3f95"
}
```

次に使うときに取り直して比べる。

- 全部一致 → 記録をそのまま使う
- 一つでも違う → 規約が書き換わっている。決め直す
- 記録に無いファイルが増えた → 決め直す
- 記録にあるファイルが消えた → 決め直す

規約が緩くなったのか厳しくなったのかは自動で判断しない。**どちらでも決め直す。**

## 検出を足す

`scripts/inspect.py` の `HUMAN_MERGE` `ONE_AT_A_TIME` `BRANCH_RULE` に
`(正規表現, 説明)` を足す。説明は報告にそのまま出るので、
何が見つかったか一読して分かる言葉にする。

足したら、当たるべき文と当たってはいけない文の両方で試す。

```bash
scripts/inspect.py /path/to/repo
```

**誤って拾うルールは、無いルールより悪い。** 規約に無いことを理由に
選択肢を狭めると、理由の分からない制限になる。
