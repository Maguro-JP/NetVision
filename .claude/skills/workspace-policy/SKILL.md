# Workspace Policy

このリポジトリで何を自動でやってよいかを、一度だけ決めて記録する。
以後は毎回尋ねない。それがこのスキルの目的。

記録は `.claude/policy/<利用者名>.json` に置いてコミットする。

## なぜこの置き場所なのか

| 置き場所 | どこでも残るか | 共同開発で競合するか |
|---|---|---|
| `~/.claude/` | 残らない。スマホや Web のセッションは毎回作り直される | しない |
| リポジトリの共有ファイル | 残る | する |
| `.claude/policy/<利用者名>.json` | 残る | しない。利用者ごとに分かれる |

利用者名は GitHub の login をそのまま使う。他人は自分のファイルを持つので、
同じ行を書き換え合うことがない。

見えて困る内容でもない。誰が自分の PR を自動マージするかは、
共同で開発するなら見えていた方がよい。

## 手順

### 1. 記録があるか見る

`.claude/policy/<利用者名>.json` があり、後述の失効条件に当たらないなら、
それを読んで終わる。何も尋ねない。

### 2. リポジトリの規約を読む

```bash
scripts/inspect.py            # 人が読む形
scripts/inspect.py --json     # 機械が読む形
```

規約ファイル（`AGENTS.md` `CLAUDE.md` `CONTRIBUTING.md` `CODEOWNERS`
`.cursor/rules/*.mdc`）と、PR で走る CI を探し、次の記述を拾う。

- 人がレビューしてマージする運用
- 同時に開いてよい PR の本数の制限、積み上げ PR の禁止
- 枝の接頭辞の指定

**このスクリプトは判定しない。材料と根拠を出すだけ。** 決めるのは人。

### 3. 選べる範囲を絞る

規約に書いてあることは、利用者の好みより優先する。

| 見つかったもの | どうするか |
|---|---|
| 人がレビューしてマージする運用 | 自動マージを選択肢から外す |
| CODEOWNERS がある | 自動マージを選択肢から外す |
| PR を1本ずつ、積み上げ禁止 | `max_open_prs` を 1 にする |
| 枝の接頭辞の指定 | `branch_prefix` に入れる |
| 規約の検査をする CI がある | その CI の名前を `policy_checks` に控える |

**規約に反する選択肢を提示してはいけない。** 尋ねてから断るのではなく、
最初から出さない。

### 4. 一度だけ尋ねる

残った選択肢を、根拠と一緒に見せる。

```
このリポジトリでの進め方を決めます。

  規約から分かったこと:
    AGENTS.md:3  人がレビューしてマージする運用
    AGENTS.md:12 PR は1本まで

  そのため自動マージは選べません。

  同時に開く PR: 1本まで（規約どおり）
  枝の接頭辞: cursor/

この内容で記録しますか。
```

規約から何も見つからなければ、自動マージの可否だけを尋ねる。

### 5. 記録してコミットする

`assets/policy.json` を元に書く。**根拠を一緒に残す。**

```json
{
  "version": 1,
  "user": "Maguro-JP",
  "repo": "Maguro-JP/Ciel",
  "decided_at": "2026-08-23",
  "auto_merge": true,
  "merge_method": "squash",
  "delete_branch": true,
  "draft_is_default": true,
  "max_open_prs": null,
  "branch_prefix": null,
  "human_review_required": false,
  "policy_checks": [],
  "evidence": {
    "policy_digests": { "CLAUDE.md": "a1b2c3d4e5f60718" },
    "note": "規約に人の関与を求める記述なし"
  }
}
```

コミットするのはこのファイルだけ。他のファイルを一緒に変えない。

## 記録の失効

`evidence.policy_digests` に、読んだ規約ファイルの内容の要約を残す。
**次に使うとき、現在の内容と突き合わせる。**

| 状態 | どうするか |
|---|---|
| 要約が一致 | 記録をそのまま使う。尋ねない |
| 要約が違う | 規約が書き換わっている。手順2からやり直す |
| 記録に無い規約ファイルが増えた | 同じくやり直す |
| `version` が違う | 同じくやり直す |

規約が変わったのに古い判断で自動化を続けるのが、いちばん危ない。

## 決めること

| キー | 意味 |
|---|---|
| `auto_merge` | 自分の PR を確認なしでマージしてよいか |
| `merge_method` | `squash` / `merge` / `rebase` |
| `delete_branch` | マージ後にリモートの枝を消すか |
| `draft_is_default` | 常に draft で PR を作る運用か |
| `max_open_prs` | 同時に開いてよい PR の本数。`null` は制限なし |
| `branch_prefix` | 枝の接頭辞。`null` は指定なし |
| `human_review_required` | 人のレビューが要るか。true なら `auto_merge` は必ず false |
| `loop_interval` | `auto-dev` のループ間隔。`null` は自動 |
| `push_policy` | `batch` / `never` / `each`。既定は `batch` |
| `policy_checks` | 規約を検査する CI の名前。落ちてもコードを直さない |

## 原則

- **規約は好みより強い。** 規約に反する選択肢は最初から出さない
- **一度決めたら尋ねない。** 失効条件に当たったときだけ聞き直す
- **根拠を残す。** なぜその判断になったかが後から分からないと、見直せない
- **判定をスクリプトに任せない。** スクリプトは材料を出すだけ
- 記録するファイル以外を一緒に変更しない

## 他のスキルとの関係

- 個々の PR をマージしてよいかの判断は `solo-pr-flow` が行う。
  このスキルはその前提となる方針を用意する
- CI の読み方は `ci-triage` が行う。`policy_checks` はそちらに渡す

検出の詳しい仕組みと、規約の書き方による取りこぼしは
`references/detection.md` を読む。
