# 当たり前の次の手順

頼まれた仕事の目的に、当たり前に含まれる手順の表。着手の前に、今の仕事に当たる行を並べ、最後までやる。
表に無い仕事でも、「これが済んだら、頼んだ人は次に何が起きていると思っているか」を 1 つ考えて足す。

## 表

| したこと | 当たり前の次の手順 | 確かめ方 |
|---|---|---|
| スキルやフックを作った・直した | 検査を通し、PR とマージのあと、配る | `./scripts/validate.sh`、`precheck.py`、`skill-sync` の `sync.py` |
| PR を作った | 同じターンで購読する | `subscribe_pr_activity`（actions-watch） |
| マージした | 配布と後片付け（購読の解除、使い終えたブランチ、手元の main ブランチ） | `sync.py`、`unsubscribe_pr_activity`、`git pull` |
| 直した | 動かす。同じ手順で再現しなくなったのを見る | 直す前に落ちた手順を、もう 1 回動かす |
| 配るファイル（スキル、フック、テスト）を変えた | 配った先の形の clone で 1 回動かす | 配った先の settings.json の形のコピーで、テストと `hooks-smoke.py --root` |
| 止められた（フック、権限、エラー） | 原因を調べる。何が止めたか、何と言えば通るかを掴む | フックの名前と読み取った文、権限の名前、エラーの文の最後まで |
| PR を作る前 | 差分のファイルの数と衝突を見る | `git diff --stat <base>...HEAD`、`git merge-base` |
| テストを足した | 落ちる所を 1 回見る | 直す前は落ち、直したあとは通る |
| 依存を足した・版を上げた | 入っている版と公式の文書を見る | `pip show`、`npm view`、`--version`、Context7 |
| 文書を書いた | 差分を読み、リンクと一覧を確かめる | `git diff`、`docs_check.py` |
| コミットした | 意図したファイルが入っているかを見る | `git show --stat` |
| 処理を裏に出した | 終わりの通知を読み、結果を ❕ で 1 行書く | 出力のファイルの末尾と終了コード |
| 調べ物をした | 知識に残す | `knowledge.py --add`（research-to-tech） |

## 聞き直さない

ユーザーが 1 回答えたことを、同じ流れの中で聞き直さない。
聞き直してよいのは、ツールの権限かフックに止められて、進めるのにユーザーの一言が要るときだけ。
そのときは、次の 2 つを 1 行で書く。

- 何が止めたか（フックの名前、権限の名前、読み取られた文）
- 何と言えば通るか（そのフックが返事として読む言い方）

同じ ❔ を 2 回出したら、3 回目を出す前に、止めた物の読み取りを調べる。
ユーザーの言葉と機械の判定が逆なら、機械の側がおかしい（[signals.md](signals.md)）。

## 機械で見る組

`hooks/followup_gate.py` が読む表。1 行が 1 組で、「したこと」が成功したターンに「次の手順」が無く、❔ で終えると差し戻す。
正規表現は Python の形。Bash の呼び出しはコマンドに、ほかの呼び出しは「ツールの名前と入力の JSON」に当てる。
表の区切りと重なるので、正規表現の中の縦棒は `\|` と書く。行を足すのは、機械で確かに見分けられる組だけにする。

| 組 | したこと（正規表現） | 次の手順（正規表現） | 差し戻しの文 |
|---|---|---|---|
| マージ | `^mcp__\w+__merge_pull_request\b\|(?:^\|[;&\|]\s*)gh\s+pr\s+merge\b(?!.*--auto)` | `sync\.py\|skill-sync\|配布\|配る\|配り` | PR をマージしたのに、次の手順（配布の開始）を始めずに ❔ で終えている |

「❕ 次: <次の手順と、いま始めたこと>」の行があれば通る。配る物が無いリポジトリでは、後片付けを始めて `❕ 次: 後片付け（配る物は無い）` と書く。
