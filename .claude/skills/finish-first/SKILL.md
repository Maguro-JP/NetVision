# 1つを完成させてから次へ

何か月も回しているのに完成した成果物が無い。原因は3つで、どれも「作業量」では解決しない。

1. 完成の定義が無い。何ができたら完成かを誰も書いていないので、いつまでも「進行中」になる
2. 複数を並行している。PR とコミットは増えるが、どれも最後まで行かない
3. 判断待ちで止まる。脇に置いた件が溜まり、成果物の中心がそこにあると全部が止まる

このスキルは、この3つを順に潰す。

## 決まりの出どころ

公開されている definition-of-done のスキルを2つ読み、要点を取り込んだ。
validkeys/sherpy（MIT）からは「確かめられる文で書く」基準と出口のチェックリストの形、
もう1つ（ライセンス表記なし。文言は取り込まず要点だけ）からは「意図・途中・かけた時間・記憶・それらしい答えは完成ではない」の5つ。
どちらも1つずつ完成させる決まりは持たないので、そこはこのスキルで足した。

## 1. 完成条件を先に書く

成果物ごとに `docs/reports/deliverables.md` に1行書く。ひな形は `templates/deliverables.md`。

| # | 成果物 | 完成条件 | 状態 | 残り | 更新 |
|---|---|---|---|---|---|

- 完成条件は、動かして確かめられる文で書く。「ログインが動く」は条件にならない。
  「メールとパスワードでログインでき、`npm test -- login` が通る」は条件になる。
  コマンド名、テスト名、画面の操作と出る結果、のどれかを含める
- ユーザーが書いた完成条件があればそれを使う。無ければ AI が仮に書き、`❔` で1行確かめる。
  返事が無くても仮のまま進める。仮であることは表の「完成条件」の末尾に「（仮）」で残す
- 状態は 未着手・進行中・確認待ち・完成 の4つ。「ほぼ完成」は無い
- 表が無いリポジトリでは、最初のサイクルで作る。README の未着手の項目、open の issue、ユーザーの優先指示から
  成果物を1〜3行に絞り、完成条件を仮で書く。`❔` で1行だけ確かめ、返事が無くても仮のまま進める。
  表が無いままだと、このスキルも auto-dev の判断表の4番目も効かない

## 2. 1つずつ

- 表の上から順に、状態が完成でない最初の行が「今の成果物」。フックが毎ターン差し込む
- 今の成果物が完成するまで、新しい成果物に着手しない。行を足すのはよいが、状態は未着手のまま
- 1サイクルの作業は、今の成果物の「残り」から取る。auto-dev の判断表では、壊れているもの・詰まっているもの・ユーザーの優先指示の次に来る
- 「残り」は、次に何をすれば完成に近づくかを1行で書き、毎サイクル更新する。
  セッションが切れたとき、次のセッションが読む唯一の手がかりになる

## 3. 判断待ちで止めない

今の成果物に関わる判断で止まりそうになったら、戻せる判断はデフォルトを選んで進める。

| 判断の種類 | すること |
|---|---|
| 設計の分岐（auto-dev の S4）、根拠が足りない（S7） | デフォルトを選んで進める。`pending.md` に「デフォルトで進めた: <選んだもの>。違えば答えを」と書く |
| 人の判断が要る（S5。仕様変更、課金、認証、本番、削除、公開、外部送信） | 進めない。何を決めてほしいかを書いて止まる。これだけが止まってよい判断 |

デフォルトの選び方は、上から順に最初に当たったもの。

1. 仕様やユーザーの過去の指示に書いてある方
2. 今あるコードと設計に合わせる方
3. あとで戻しやすい方（追加だけで済む、設定で切り替えられる）
4. 単純な方

選んだことは記録に「AI の判断」と分かる形で書く。ユーザーが違うと言えば、その場で戻す。

## 4. 完成の判定

完成と言えるのは、完成条件の文をそのまま実行して、その出力を見せたときだけ。手順は `verify-before-done`。

次の5つは完成ではない。

- 意図した。「X をするつもりで作った」は、X ができたことではない
- 途中まで進んだ。「X を始めた」は、X が完成したことではない
- 時間をかけた。「X に半日かけた」は、X が動くことではない
- 前に確かめた記憶がある。状態は変わる。もう一度動かす
- それらしい答えがある。確かめていないテストの出力や、作った説明は完成の証拠にならない

完成したら、状態を完成にし、日付を入れ、出力か PR の URL を「残り」の欄に置く。
会話には `★ 完成 <成果物>: <PR か出力の場所>` の1行。

## 5. フックが差し込むもの

`hooks/focus.py`（SessionStart と UserPromptSubmit）が `docs/reports/deliverables.md` を読み、
先頭の未完成の行を「今の成果物・完成条件・残り」の1行にして差し込む。
表が無いリポジトリでは何も出さない。完成条件が確かめられる文になっていない行には注意を出す。
`FINISH_FIRST_OFF=1` で止まる。

## 6. 他のスキルとの関係

- 1サイクルの作業の選び方: `auto-dev`（判断表の3番目にこの表の「残り」が入る）
- 日報: `dev-report`（先頭の未完成の成果物と残りを1行載せる）
- 判断待ちの一覧と答え: `pending`
- 完成の検証の手順: `verify-before-done`
- トピックごとのセッション: `feedback-session`（1トピック = 1成果物として、この表に行を持つ）
