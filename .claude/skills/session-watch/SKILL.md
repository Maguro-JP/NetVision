# セッションの見張り

AI が作ったセッションは AI が責任を持って管理する。催促も待機もクローズも AI がする。
人が開いたセッションは人のもので、見ない・聞かない・知らせない。人の邪魔をしない。
一覧を人が毎回読み分けるのは続かないので、機械で判定し、処置まで進める。

## 手順

1. 一覧を取って、ファイルに書く。`list_sessions(mine=true, limit=100)` と `list_triggers(limit=100)`（複数ページは配列をつなげる）の結果を、
   scratchpad の `sessions.json` と `triggers.json` に書く。MCP の一覧は Python から呼べないので、ここだけ手で写す
2. 判定する

```
python3 .claude/skills/session-watch/scripts/judge.py --sessions sessions.json --triggers triggers.json --clones /home/user --json actions.json
```

3. 処置する。`actions.json` の順に、消す（archive）→ 無効にする（disable）→ 催促（nudge）

| 判定 | 根拠 | 処置 |
|---|---|---|
| サボり | 有効なルーティンに紐づき、直近の実行は成功なのに、そのリポジトリのデフォルトブランチに 3 日間コミットが無い | 催促。`fire_trigger` の text に「前回から成果が無い。今日の分を進める」 |
| 落ちた | `status_bucket` が FAILED で、理由が上限ではない | 催促。ルーティンがあれば `fire_trigger`。無ければ 1 回きりのルーティン（下）で起こす。AI が立てて落ちたまま 3 日以上でルーティンが無ければ「無駄」 |
| 答え待ち | BLOCKED か REQUIRES_ACTION | 問いが PR・マージ・push・リリースの確認なら待機（ユーザーの ❔ の返事でしか進まない。催促しない）。それ以外で AI が立てたものなら催促（「戻せる判断はデフォルトで進め、戻せないものは pending.md に書いて次へ」）。人のセッションなら待機 |
| 動いたまま止まっている | RUNNING のまま 1 日以上動きが無い | 1 日で待機、3 日で `interrupt_session` で止めてから催促（AI が立てたものだけ。人のセッションは止めない） |
| 上限で止まった | 理由に weekly limit か rejected | 待機（patrol の決まり）。戻ったら次の実行で動く |
| 宙に浮いたルーティン | 有効なルーティンの紐づけ先が、AI が立てて消したセッション | `update_trigger enabled=false` で無効にする。紐づけ先が一覧に無い（人のセッションか、一覧の外）なら待機 |
| 無駄 | AI が立てた（`parent_session_id`、tag `feedback-session:`・`ciel:`・`config:meta-mcp-own-entry`、origin が claude_code_mcp_seed）、ルーティン無し、3 日以上動いていない | `archive_session` で消す（`unarchive_session` で戻せる）。`feedback-session:keep` の付いたものは残す |
| 分からない | ルーティンの先のリポジトリの clone が手元に無い | 待機。clone を置けば次から判定できる |
| 回っている・動いている・待機 | 上のどれでもない | 無し |
| （見ない） | 人が開いて、ルーティンに紐づいていない | 表に出さない。消さない・聞かない・知らせない。数だけ最後の行に出す |

ルーティンに紐づいたセッションは、人が開いたものでも、ルーティンの動き（サボり・落ちた）だけは催促する。
ルーティンは AI が立てたもので、起こすのはルーティンが毎回していることだから。消す・止めるのは AI が立てたものだけ。

催促でルーティンが無いとき: `create_trigger`（`persistent_session_id` にそのセッション、スケジュール無し、name「催促」）→ `fire_trigger(text)` →
`delete_trigger`（消せなければ `update_trigger enabled=false`）。

4. 会話には ❕ で 1 行: `❕ セッション: 消した N、無効にした N、催促 N、待機 N`。表は週報（skill-upkeep）に貼る。聞かない・知らせない

## 決まり

- 人が開いたセッションには触らない。消さない・止めない・聞かない・知らせない。人の邪魔をしない
- 消すのはアーカイブ。消せないもの（ツールの権限で止められた）は週報に名前を書く
- 催促は 1 日 1 回。催促しても成果が出ないものは、プロンプト・枠・リポジトリ側の詰まりを週 1 回の skill-upkeep で見る
- 走っているセッションのブランチ・PR・ルーティンには触らない。判定と処置だけ
- 週 1 回の skill-upkeep の観察のあとに回す。毎日は回さない（トークンの無駄）

## スクリプト

| 何 | すること |
|---|---|
| `scripts/judge.py` | 一覧から判定と処置を出す。`--days`（サボりと無駄の日数、既定 3）。clone はデフォルトで取り直す（`--no-fetch` で止める。取り直さないと古い clone で動いているものがサボりに見える） |
| `scripts/test_judge.py` | 作った一覧と一時的なリポジトリで、判定と処置を確かめる |

## 他のスキルとの関係

- 全体を表で見る: `patrol`。止まっているかの判定の元はそこ。このスキルは処置まで進める
- ブランチ・一回きりのルーティン・終わったセッションの整理整頓: `tidy`。このスキルの「無駄」は tidy の「終わったセッション」と同じ判定で、毎日回す
- セッションを立てるときの設定と、立てた側での整理整頓: `feedback-session`
- 定期実行: `scheduler`。週の報告: `skill-upkeep`
