# 自律的に学ぶ

Claude の重みは変わらない。ここで言う「学ぶ」は、調べて確かめたことを、次のセッションが
読める形でリポジトリに残すこと。会話の中だけで分かった気になっても、次の日には消えている。

## 先に決めること

学び始める前に、目標を判定できる形にして、学習ノートの先頭に書く。

| 決めること | 例（HD-2D のドット絵） |
|---|---|
| 何ができたら学んだと言えるか | 戦士を描いて、作風の決まりの検査を全部通り、参考と並べて同じ作風に見える |
| どう判定するか | `tools/check.py` の通過数と、並べた画像を見ての判定 |
| 今どこにいるか | 6項目中5つ通過。見た目は量産型のインディー風 |
| どこで諦めるか | 3周続けて判定が上がらない、または資料が手に入らない |

判定の方法が決められない目標は、学び始めない。決められないこと自体を判断待ち
（`docs/reports/pending.md`）に書く。判定がないまま回すと、調べた量を成果だと思い込む。

## 1周の流れ

1. 調べる: 一次資料（公式の文書、開発者の記事、仕様、論文）を先に当たる。出典の URL と、何が書いてあったかを1行ずつ控える。断られたサイトや読めなかった資料も控える
2. 決まりに落とす: 分かったことを、数えられるか確かめられる形に直す。「かっこよく」ではなく「18x32、色は20以内、輪郭に純黒を使わない」。機械で確かめられるものは検査のコードにする
3. 練習する: 決まりを使う小さな課題を1つ作って解く。いきなり本番の大きさでやらない
4. 判定する: 先に決めた方法で判定する。数字と、見たもの（画像、出力）をそのまま残す。前のサイクルと並べる
5. 記録する: 効いたこと、効かなかったこと、次に試すことを学習ノートに書く。効かなかったことも消さない。同じ道を二度通らないため

判定が通れば止まる。通らなければ、効かなかった理由から次のサイクルの仮説を立てて戻る。

## 残す場所

```
docs/knowledge/learning/<トピック>.md   学習ノート（目標・判定・サイクルごとの記録・出典）
styles/ や rules/ など              決まりそのもの（そのリポジトリの置き場に合わせる）
tools/ や test/                     決まりを確かめる検査
```

学習ノートの形。

```
# <トピック>
目標: 何ができたら学んだと言えるか
判定: どう確かめるか
現在: 最新の判定の結果
諦める条件:

## サイクル1（YYYY-MM-DD）
仮説:
やったこと:
判定: 数字と、見たもののパス
効いた / 効かなかった:
次:

## 出典
- URL — 何が書いてあったか（読めなかったものは「読めなかった」と書く）
```

次のセッションは、作業の前にこのノートの「現在」と最後のサイクルの「次」を読む。

## 止まる条件

| 条件 | すること |
|---|---|
| 判定が通った | 止まる。ノートの「現在」に通ったことを書く |
| 3周続けて判定が上がらない | やり方が頭打ち。今のやり方の限界と、別のやり方の案をノートに書き、判断待ちに出す |
| 資料が手に入らない（ネットワークで断られる、有料） | 何が要るか（ドメイン、資料名）を判断待ちに書き、手元で進められる部分だけ続ける |
| 学んだことが人の判断に関わる（著作物を写す、課金、公開） | 実行しない。判断待ちに書く |

## long-dev が回っているリポジトリで使うとき

1つのセッションは一度に1つのことしかしない。学習で auto-dev を止めない。

- 学習の1周（調べる→決まり→練習→判定→記録）を、auto-dev の1周として回す。サイクルの終わりは auto-dev と同じ。コミットし、次の実行を予約してから返答を終える。学習の途中でも、予約せずに終えない
- 学習ノートの「次」が、次のサイクルの仕事になる。優先の指示や日報の優先に学習が載っていれば続け、載っていなければ auto-dev の順序で選ぶ
- 翌朝の Routine で auto-dev が回し直されても、ノートは残る。次のサイクルがノートの「現在」と「次」から続ける
- 学習を、開発と並べて同時に進めたいときだけ、別のセッションで回す。`scheduler` の手順でそのリポジトリを渡したセッションを作り（Routine は作らない。学習は判定が通るか頭打ちで終わる）、学習のブランチ（例 `claude/learn-<トピック>`）だけに書き、終わったら1本の PR でマージする。トークンは2倍かかる

「1リポジトリに1セッション」は、同じブランチに2つのセッションが push しないための決まり。ブランチが別なら2つでよい。

## やってはいけないこと

- 判定をせずに「学んだ」と言うこと
- 調べた量や、書いたノートの長さを成果として報告すること
- 参考にした作品や文書を、そのまま写してリポジトリに置くこと。置くのは決まりと出典だけ
- 出典のない断定を決まりに入れること。推測なら「推測」と書く
- 効かなかった試みをノートから消すこと

## 会話に出すもの

work-style の4種類だけ。`❕ 学習 N周目: <調べること1行>`、`★ 学習 N周目: <判定の結果を数字で1行>`、
`❔ 学習: <決めてほしいこと1行>`。調べた中身と出典は学習ノートに書き、会話には貼らない。

## 他のスキルとの関係

- 自分の判定の誤りの記録: `lessons`。学習ノートはできるようになるための記録で、別のもの
- サイクルごとの開発: `auto-dev`。根拠が足りない（S7）ときに、このスキルで調べてから戻る
- 終わりのない開発: `long-dev`。学習のサイクルも auto-dev のサイクルとして回せる
- 完了と言う前: `verify-before-done`
